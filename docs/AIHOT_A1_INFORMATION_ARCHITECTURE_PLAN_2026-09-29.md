# AIHOT 信息处理机制与 A1 结合方案

日期：2026-09-29。范围：源码研究与实施设计，不是已完成接入、部署或策略收益验收。

## 用户补充后的接入定位：A2 优先，事实回流 A1

用户进一步提出作为 A2 情绪面的补充。调整实施定位：**共享资讯事件层，先旁路辅助 A2 的题材发现与催化分析，经过核实的经营事实再回流 A1**。下文 A1 证据与代际设计保留，但不再要求先完成全部 A1 改造才能验证资讯价值。

A2 保留四条独立证据轴，不把新闻热度直接替代现有板块强度：

| 证据轴 | 回答什么 | 不应推断什么 |
|---|---|---|
| 资讯催化 | 为什么此时出现关注，事件是否新、重要、可核实 | 有利好就一定上涨 |
| 传播情绪 | 关注是否扩散、加速、集中或开始分歧 | 多家转载就是多份独立证实 |
| 市场确认 | 板块相对强弱、上涨广度、成交活跃和已有可用资金数据是否支持 | 新闻条数等同资金流入 |
| 个股角色 | 是主营直接关联、板块领涨、趋势中军还是跟随 | 所有概念成分股都应晋级 |

处理顺序：事件去重与时间校验 → 本地题材/主营映射 → 与现有量化板块及个股事实合并 → LLM 分析催化、分歧、角色和证据缺口 → 原有资格规则决定去向。保持量化与证据先行，不让模型单独指定五个板块。

可以形成四类中文说明：

- 催化与市场共振：有新事件，板块及核心个股也得到量化确认，进入正常 A2 审核。
- 有催化、尚未确认：形成观察记录，不能伪装成强势板块；无新闻的强趋势也不能因此被排除。
- 行情强、原因待核实：保留技术/轮动路径，继续补证，不因找不到新闻机械拒绝。
- 高关注但分歧加大：检查冲高回落、广度收缩、负面修订等实际证据，不把热度最高等同最适合买入。

资讯层不得直接判定情绪周期。周期判断仍需连板/涨跌停、晋级率、炸板、广度等实际可用数据；缺项明确标注，不能由标题情绪推导“冰点”或“高潮”。资金数据缺失亦不得由资讯模型补造。

原有聚焦前五个板块仍按当前已确认规则执行。新增资讯只在旁路列出“催化新方向及未聚焦原因”，先测是否减少漏识别；如果要改生产聚焦排序，单独做固定输入的对照验证，不暗改权重或通过扩容制造改善。

A2 发现池外公司时，可发起 A1 定向重审，但只有正式进入同一有效 A1 代际后才能晋级 A2/A3，避免破坏集合包含关系。

对应首期交付改为：一个可核实免费来源的增量事件采集 + A2 事件证据旁路投影 + 既有板块结果对照表。比较“仅行情/人气”与“增加去重催化”的提前发现时间、误关联、漏识别和资源占用；不以更多信号为验收目标，也不直接修改 A4。

## 1. 结论

建议吸收 AIHOT 的“统一采集入口、资料版本、事件归并、分析回执、来源健康、固定评测集”，在现有系统增加一层**可追溯的产业事件与公司证据层**，而不是部署整套 AIHOT，也不是把新闻评分变成选股评分。

目标不是让 A1 读更多文章，而是让每个可能改变公司经营判断的事件，及时、去重地进入对应股票的证据档案，并能回答：何时知道、依据什么、影响哪个业务、是否足以改变入池判断。

保留既有分工：A1 判断基本面与产业方向，A2 判断市场关注和轮动，A3 判断技术资格，A4 判断执行条件。新闻热度不能替代财务证据，也不能越过技术和风险条件直接形成买点。

## 3. AIHOT 实际怎样处理信息

### 3.1 采集不是一个爬虫，而是可配置的数据源任务

支持 RSS、网页列表、JSON 列表、X、公众号及外部推送。来源有独立游标、成功时间、失败次数、参与方式和轮询间隔。采集后先存资料，再排队处理；失败不推进成功游标，失败退避与预算不足分开处理。

源码还有单次数量限制、首次导入限制、详情抓取预算和 RSS 条件请求。未知配置会显式失败，而不是悄悄忽略。

可借鉴：每个源独立失败，不拖死整轮 A1；先持久化再确认进度；只处理新增和修订。

需改进后采用：普通列表一次截取最多 60 条，若高峰超过窗口或列表本身不分页，不能单靠“成功”保证不漏采。我们的公告采集必须保存分页续点、覆盖区间和积压量，只有完整遍历或明确断点持久化才宣称该区间已覆盖。

### 3.2 资料先有身份和版本，再被模型分析

`content/materials.ts` 是统一入口，管理 URL 身份、正文哈希、修订和时间归属。新资料与旧资料修订都能触发后续处理。

它把首次发现时已经超过 48 小时的旧材料归为历史，不当作今日新消息推送。这个思路能防止旧闻重炒，但**不能直接套到财报**：半年报可能数月内仍是最新有效证据，只是不能把今天补采当作今天发布。

### 3.3 相关性、新闻质量、结构化分开

先宽召回预筛，只有 BLOCK 停止，PASS/UNKNOWN 继续；随后两次独立评分，与来源等级对应阈值比较。源码的两次评分是**同一选定模型的两次顺序调用**，不是两个独立事实源，也不能理解成双模型事实核验。

结构化独立抽取主体、动作、对象、发生日期及主题，之后形成摘要。这适合新闻编辑，但它的“值得关注”不等于“盈利改善”或“股票符合策略”。我们不照搬评分阈值，也不引入其模型配置。

### 3.4 从文章提升到事件

关系判断区分同一事件、同一故事的新进展、不相关、综述。这个区分比只做标题相似去重更有价值：合同签订、后续履约、取消合同应关联，但不能合并成同一条事实。

我们需要额外增加否认、纠正、撤回和失效关系，且修改的是新事件版本，不能覆盖历史决策所见的原版本。

### 3.5 热度不是文章数量

热榜按最近 48 小时的参与者计数，同一参与者只计一次，使用 24 小时半衰期；还考虑采集落后对趋势比较的影响。

应借鉴“去重复传播、说明覆盖不足”，不照搬周期和阈值。不同网站转载同一篇公告，仍可能只是一个信息起点；网站数不等于独立事实确认数。

尤其注意：源码允许补齐历史热度图，这适合展示，但交易回放必须另用当时已接收的版本，不能把后来发现的信息补进过去决策。

### 3.6 调用回执和评测有实际价值

付费调用在发送前登记，响应先落盘再写业务结果，绑定输入修订、模型及提示词版本，恢复时复用已收到的响应，避免一次任务故障不断重新收费。

SelectBench 用标注样本比较筛选效果，值得采用。但模型自报置信度和新闻精选分不是经校准的投资概率。

## 4. 与当前 A1 的差距：不是从零开始

| 已有能力 | 本次应补的环节 |
|---|---|
| `config/a1_research_sources.yaml` 来源分级与使用范围 | 每个源的实际增量入口、覆盖区间、延迟和失败账本 |
| `pipeline/a1_sources.py` 冻结来源契约 | 从原始文章到可核查业务事实的完整链路；该文件本身不是爬虫 |
| `config/a1_evidence_contracts.yaml` 财务、主营、催化和估值契约 | 逐字段执行与缺口状态；当前配置为 `DIAGNOSTIC_SHADOW`，不能宣称全部硬性生效 |
| `a1_registry.py` 股票池代际与 `a1_coverage.py` 覆盖/补采 | 将新事件定向触发受影响公司的增量补证和重新审核 |
| `a1_packet.py` 模型投影 | 按事件版本和证据 ID 输入，不重复灌入资讯全文 |
| 本地主营/行业映射、`early_discovery.py` | 主营映射支撑新闻关联；技术早发现继续保留，不将它误称为已有新闻发现能力 |

数据源登记成功、网络连通、任务退出成功、真正补齐有效证据，是四个不同状态，页面和验收必须分开。

## 5. 建议架构

```text
免费公开来源 → 有界增量采集 → 原始资料与修订档案
                                  ↓
                    时间/单位/实体校验 → 事件归并
                                  ↓
                 公司主营映射 + 财务底座 + 引用证据
                                  ↓
                      规则预审 → 有界模型分析
                                  ↓
                A1正式增量 / 待补证观察 / 不符合
                                  ↓
                  A2情绪轮动 → A3技术 → A4执行
```

原文按来源权限保存在独立资料存储，冻结研究包保存必要片段、文件哈希和证据索引；不是把所有原文再次嵌套到已经很大的研究快照。模型不得在执行阶段任意联网补事实。

### 5.1 免费源分工

下表是接入优先级，不是本轮已验证可用的接口清单；每个具体入口先验证访问范围、分页、日期和限频。

| 类型 | 优先来源方向 | 对 A1 的作用 |
|---|---|---|
| 财报、公告、风险 | 巨潮、交易所、上市公司公开披露 | 主营、利润、现金流、订单及风险证据主干 |
| 宏观、政策 | 部委、统计局等官方公开发布 | 政策原文、实施时间、适用行业；不直接推断个股必然受益 |
| 产业变化 | 行业协会、公司官网、公开产品/调价通知 | 提价、产能、供需及产品进展；区分发行人主张与已验证业绩 |
| 财经媒体 | 可公开访问且可规范采集的财经资讯 | 发现线索并追溯原文，不能代替公告证明合同和收入 |
| 股吧、热门榜 | 现有可用东方财富等链路 | 主要供 A2 关注度；触发 A1 查证，不能成为基本面确认 |

免费优先仍需做来源故障隔离，不把“另一家转载网站”视为财务数据替代。AIHOT 的 X/SocialData、公众号/Dajiala、可选 Jina 路线不纳入免费首期。

### 5.2 事件与证据最小契约

建议逻辑实体：`source_runs`、`materials/revisions`、`events/revisions`、`event_stock_links`、`analysis_receipts`、`a1_event_decisions`。复用现有存储适配和迁移体系，先审查已有表，不直接新建另一套数据库。

每条事件至少保存：

- 身份：事件 ID、版本、原始资料 ID、正文哈希、上游原始出处、转载链。
- 时间：原文发布时间、事实发生/生效时间、首次发现、接收时间、分析完成时间；时区明确，未知不能补猜。
- 事实：主体、动作、对象、金额/单位、状态、来源位置或页码；数字必须能回到原文。
- 关联：股票代码、关联角色、主营依据、映射版本、直接或间接受影响、映射疑点。
- 判断：支持证据、反证、缺项、规则版本、模型/提示词版本、结论及失效条件。

文章可能含多个事件，事件可能关联多家公司，公司可能在产业链中受益或受损。不能“命中关键词就全部利好”。正文中的命令和提示词注入一律作为不可信内容，不能更改工具权限或审核规则。

### 5.3 公司关联先查证，再谈利好

例如“覆铜板提价”只是一条产业线索。正确流程：确认谁提价、产品规格、时间和原始通知 → 本地主营证据找实际生产商及收入敞口 → 分析原材料成本与传导 → 检查财务底座 → 列出尚不能确认的订单及利润影响。

不因为股票贴有 PCB 标签就认定受益；下游采购商可能面临成本压力。送样、认证、小批量、规模量产、收入确认必须分别记录。

“签订 8 亿元合同”也不能直接算成当期新增利润：需核对履约年限、约束条件、关联交易、历史营收口径，无法确定的数值不估填。

### 5.4 不做一个不透明综合分

分别输出：来源与证据质量、主营相关性、经营影响、信息新旧及修订、市场关注度。确定性代码负责可计算值与缺失检查；模型解释传导机制、反证和不确定性。

首期沿用既有 A1 准入标准，不修改阈值。新增输出应能写成：“某日某公告确认什么 → 对公司哪个业务有何作用 → 财务支持是什么 → 尚缺什么 → 为什么维持/重审/观察”，不能写成“热点强、综合评分高”。

## 6. 月度 A1 与每日资讯如何平衡

1. 月度确定基本投资方向和研究底座；周度补财报、主营、风险和方向证据，不每日全量重跑。
2. 每日事件只重审**受影响的公司集合**，包括池外已完成基础筛选但缺催化的公司；不能只盯当前池，否则永远发现不了池外标的。
3. 池外公司必须完成原有财务/主营/风险审核才能正式进入 A1；证据不足保留观察与补采任务，不拿新闻补造缺项。
4. 新增资格通过正式 A1 代际发布，再供 A2/A3 消费同一版本，保持 `A1 ⊇ A2 ⊇ A3`。保留准入、撤回和证据差异。
5. 盘中采集可以继续，但不偷偷改写已冻结的 A3/A4 计划。重大风险走明确的现有风控路径；普通消息进入下一次约定研究刷新。
6. 日热榜变化不自动淘汰 A1 基本面合格股票，也不要求每只趋势票进入股吧前 100。

“已在 A1、未进入 A2”和“根本没发现”必须分开统计，才能判断信息补充究竟解决哪个阶段的问题。

## 7. 性能、可靠性与新鲜度

结合当前 A1 内存优化，不建议额外部署 AIHOT 的完整 PostgreSQL/队列/前端栈。

- 首期一个有界采集工作进程；PDF 解析和模型分析与 A4 执行分离。具体并发和内存上限由同机压力测试确定，不凭空承诺占用。
- 原文流式落盘、列表分页、解析单文档限额、事件级重试；大 PDF 超限明确待处理，不截断后伪装完整。
- 规则先去重、检查时间和关联范围，再调用现有火山方舟 `deepseek-v4-pro`。不照搬每篇预筛、双评分、结构化、摘要的多轮调用。
- 用事件版本、输入哈希、模型及提示词版本绑定回执；未知结果不盲目重发，预算配置缺失默认阻断付费调用。AIHOT 回执代码在预算行缺失时不限制，我们不能照搬这一默认值。
- 轮询间隔按来源及许可设置，可先以 15–60 分钟为试验范围；公告高峰优先处理积压而非只读最新首页。此范围是方案参数，不是已测延迟承诺。
- 分开记录发布至发现、发现至分析、分析至 A1 生效三段延迟。对没有可靠发布时间的资料，第一段显示不可测。
- 告警针对连续失败、未覆盖窗口、积压增长和有效证据陈旧；“这段时间没有新闻”不是故障。
- 发布失败保留原有效 A1，但必须显示过期程度和受影响范围，不能静默把旧池叫最新。

## 8. 实施次序与交付

| 阶段 | 实际改动方向 | 验收输出 |
|---|---|---|
| P0：基线 | 核对现有来源真实入口、更新周期、覆盖账本；固定当前 A1 缺口样本 | 来源可用/未接入/失效分开；基线延迟与缺项清单 |

| P3：A1 增量 | 扩展 `a1_packet.py`、既有筛选及 `a1_registry.py`；接入 `workflow.py` 约定研究任务 | 模型输入可追溯、池外重审、正式代际与集合包含检查 |
| P4：对照评估 | 冻结同时间输入，旧流程/加资料/加模型解释分层对照 | 覆盖、新鲜度、误配、资源和下游增益独立报告 |
| P5：有限启用 | 先官方事实增量，后媒体线索；保留独立开关和回退代际 | 生产运行证据、任务及发布账本，不以健康接口代替验收 |

优先顺序：公告/风险/主营补证 → 政策和产业事件 → 媒体发现 → 社交传播补充。不要一次接几十个源，让故障和信息噪声同步增长。

## 9. 测试与验收标准

以下为拟定门槛，均未在本轮执行。

### 必须逐例通过的反例

1. 同公告十家转载只算一个事实；同公司两份不同订单不能误合并。
2. 合同取消、业绩更正生成新版本，旧冻结决策仍能复现。
3. 旧半年报今天补到：补齐基本面，不计今日催化；新公告跨时区不穿越。
4. 采集第二页失败：保留断点；恢复不漏页，游标不提前推进。
5. 同名公司、子公司、供应商和客户关系不串股；行业关键词没有主营证据时不自动准入。
6. 模型产生无引用数字、引用不存在或发生时间晚于决策时点：审核不通过。
7. 模型超时/崩溃恢复不重复消费已完成回执；来源失效不阻塞 A4。
8. 原文修订或源撤回后显示冲突/失效，不能只保留最乐观摘要。
9. A1 发布前故障不切换有效代际；A2/A3 使用同一 A1 版本且集合包含成立。
10. 历史回放按 `received_at <= decision_at` 读取当时版本，后来补采只用于事后诊断。

### 分层指标

- **数据覆盖**：在有明确完整列表的抽样窗口，比对公告/事件 ID，而非比较采集篇数；零漏项反例通过后再扩大范围。全网召回率无法准确计算，不虚报。
- **映射质量**：人工标注直接关联、间接关联、无关、风险四类，开发集与留出集分离；建议留出集直接关联精确率至少 95%，同时报告召回率与置信区间，不以低召回换漂亮精度。
- **时效**：按源报告 P50/P95 三段延迟、积压最长时间；先测现状再设正式 SLA。对已公开可采来源，可先试验“至少 95% 样本在两个配置轮询周期内发现”。
- **A1 增益**：新增有效证据数、实际补齐字段数、正确新增/撤回资格、待补证下降量；不得以入选数变多作为成功。
- **资源**：采集、解析、投影、模型、发布分段 RSS/耗时，观察与 A4 同机运行时的分钟任务截止情况。
- **策略**：后续才研究 A2/A3 晋级与 T+N，固定原有阈值、计入负样本和实际可执行性，信息覆盖改善不等于收益改善。

准备至少 100–200 个跨行业标注事件，包含转载、旧闻、澄清、负面及无关样本；华正新材等历史遗漏只作为部分案例，不能围绕已知上涨股倒推规则。历史接收证据缺失的样本标“事后研究”，不冒充当时可知回放。

## 10. 方案复核

第一轮：业务边界。已剔除“新闻分数决定选股”“热榜决定基本面”“用旧闻排除规则删除财报”的不当迁移；保留 A1 月度/周度底座与日度正式增量。

第二轮：工程与证据。已补充分页截断风险、修订的双时间回放、付费预算缺省、全文内存膨胀、A4 隔离和模型无引用输出阻断。两轮均为本次方案自审，不是独立外部评审或测试通过。

下一条具体操作：先对现有 A1 来源完成“真实入口—字段—更新周期—游标—最近有效证据”矩阵，在冻结样本上实现一个官方公告源的旁路增量及修订测试，不先接入新闻评分或改生产选股。
