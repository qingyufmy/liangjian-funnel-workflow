# A1—A5 多维研究档案与 A3 分流修复：详细迭代方案

日期：2026-09-08。版本：1.1。状态：已完成两轮方案复核；R1 展示子批本地验收通过、盘后待部署，其余任务未完成。进度见 `A3_R1_IMPLEMENTATION_2026-09-08.md`；先贯通现有证据，再分批补齐研究维度。

本文件承接《A3 淘汰列表专项诊断》及随后确认的“基本面、情绪面、技术面共同研究同一标的”方向。交付的是实施明细，不表示下列代码、数据迁移、回放或部署已经完成。当前对话中的“按照这个方案继续”按正在讨论的分期顺序落实到方案，不据此直接更改盘中计划。

## 1. 目标与不变边界

目标不是新增更多模型或更多股票名单，而是做到：

1. 任何入选、观察、否决和数据缺口，都能解释“什么条件、什么数据、何时判断、依据哪里”。
2. 点开同一股票或指数，能看到基本面、技术面、情绪、宏观、行业五个视角；事实、观点、推断和执行资格相互区分。
3. 研究档案持续存在，某一天没有技术买点不抹掉公司研究价值；只有正式执行漏斗决定能否进入 A4。
4. 沿用确定性量化先行、模型分析协作；一次打开即可看全，不等于每次运行五个独立模型。
5. 保持免费数据优先、本地落盘、版本化更新与既有轻量部署方式。

不可随本次展示／档案升级改变的边界：

- A1 为月度基本面研究锚点，周度更新；新增重大事实可触发局部复核。
- A2 为情绪与轮动主导，情绪票、趋势票双通道并存；趋势轮动前五方向，人气前百为情绪线索域，不是自动合格池。
- A3 使用月线背景、已闭合周线与日线完成技术前置，保留未完成周期的观察属性；不以未来分钟信号作为 A3 入选必需输入。
- A4 负责当日盘中策略确认和风险控制；A5 回填判断表现，不自动修改生产策略。
- 保留龙头、520、趋势五日线三套策略，不新增策略，不直接采用友商 40%／30%／30% 权重，不恢复 A3 综合打分。
- 保持 DeepSeek 当前生产主路径，不重新引入 Kimi、GLM；不因增加专家视角增设五道串行模型流程。
- 不引入真实账户或真实订单，不因修正页面状态发布新计划。

## 3. 总体结构：研究档案与执行漏斗分离

```text
本地版本化事实：公告／财报／宏观／板块与成员／行情／人气
                         │
           确定性计算＋按阶段复用模型判断
                         │
        同一标的研究档案：五维观点、证据、分歧、历史
                         │ 关联，不替代执行权限
       A1 正式研究成员 → A2 有效候选 → A3 技术合格
                                             │ 正式发布
                                      A4 盘中确认与模拟
                                             │
                                      A5 与 T+N 表现回填
```

### 3.1 五个视角、三个阶段、不同更新节奏

| 视角 | 主要职责归属 | 输出问题 | 不得越权 |
| --- | --- | --- | --- |
| 基本面 | A1 | 如何赚钱、盈利质量、主营匹配、估值与风险 | 不给盘中指令，不把媒体题材当收入证据 |
| 宏观 | A1 维护，A2/A3 引用 | 政策、需求、成本与流动性如何传导 | 不用宏观乐观覆盖个股硬否决 |
| 行业 | A1 建框架、A2 评当期轮动 | 产业格局、成员关系、强弱、公司地位 | 不把父子板块当五个独立方向凑数 |
| 情绪 | A2 | 关注、资金、价格、拥挤是否共振，当前角色与周期 | 不把人气等同资金，不把趋势股排除在外 |
| 技术 | A3；盘中执行为 A4 | 哪套策略成立，具体缺什么条件 | 不重算服务器价格，不把背景风险当技术否决 |

### 3.2 集合关系与池外研究

- 为每个批次定义同一口径的集合：`A1_formal` 为本次引用的正式研究成员；`A2_effective` 为允许进入技术扫描的聚焦及合规观察成员；`A3_qualified` 为技术及复核通过的研究集合；正式发布单独计数。
- 验收 `A3_qualified ⊆ A2_effective ⊆ A1_formal`，同时验证扫描输入与候选目录一致。不得以 A2 聚焦数代替 A3 输入数。
- 任意全市场标的可有研究档案、线索和缺口说明，但有档案不等于加入 A1。
- 前百新增且不在 A1 的股票先形成快速研究请求；完成 A1 必要核验后，才形成带来源、时间、版本的正式补充成员，之后的 A2 运行引用新版本。未完成的请求不可绕过集合约束。
- 月度核心版本保持稳定；周度和事件补充采用可追溯增量版本，保留加入、移出原因。不得在查询档案时偷偷扩容 A1。
- A1 200+、至少五个方向等既有覆盖诉求作为覆盖诊断目标，不能成为硬凑股票或降低证据门槛的理由；规模不足必须给出逐方向漏斗及缺口。

## 4. 数据与状态契约（以下新增名称均为拟议，不是现有接口）

### 4.1 不再用一个“状态”承载四种含义

| 维度 | 拟议字段 | 含义 |
| --- | --- | --- |
| 技术资格 | `technical_eligibility` | 沿用量化的合格／观察／否决／数据缺口事实 |
| 证据充分性 | `evidence_state` | 当前条件所需证据是否完整、过期、冲突 |
| 模型复核 | `review_state` | 未送审、待复核、通过、否决、失败，不把未送审写成模型否决 |
| 正式发布 | `publication_state` | 来自正式发布记录；未核验到、歧义、待复核、有效、失效分别呈现 |
| 只读展示分组 | `display_disposition` | 由上述事实派生；不能作为交易授权输入 |

保留原 `status`、`local_partition`、`deterministic_*`、原始池及版本供审计。第一版投影兼容旧结果，新的规范字段只增不破坏旧消费者。未知版本默认不可发布，不默认合格。

首批兼容落地方式：现有 `ResearchPool` 只有 approved／watch／rejected 三种，不直接给原 `pool` 塞入第四个值。保留旧接口和原池字段，增加独立的展示分组字段／筛选参数及分组计数，由新前端使用；旧客户端继续按旧契约读取。研究结果增加规范化分流扩展时，先确认 schema 允许且读者已支持；若需改正式池结构则显式升版，不能手改生成的 TypeScript 类型绕过 Python 契约。生成文件统一由既有契约导出脚本更新。

对于“数据缺口＋硬否决”并存的华兴源创：仍保留原量化 DATA_GAP，不擅自重写为新策略结果；主因可优先显示独立硬否决，并显著列出题材阶段缺口。数据缺口数量与否决标签数量必须注明可能重叠；互斥主分类的总数仍须与输入对上。

### 4.2 条件级原因

新增统一条件投影，包含：

- `condition_id`、`category`：硬否决、证据缺口、技术未满足、背景风险、A4 延后确认、已通过。
- `condition_state`、`actual_value`、`threshold_or_rule`、`unit`、`timeframe`。
- `fact_as_of`、`source_ref`、`decision_id`、`rule_version`。
- `summary_zh`：确定性模板生成，依据实际字段，不依赖模型临场翻译。

主因顺序：独立硬否决 → 阻断判断的证据缺口 → 真实未满足条件。若只有背景风险或 A4 后续条件，不能显示 A3 淘汰；将其列在对应独立区域。主因之外保留全部失败条件，禁止只展示第一条就隐藏其余。

例：天音控股旧记录应显示“9 月 7 日收盘 9.05，低于五日均线 9.102；其他日线合格路径未确认”，同时另列月／周线背景偏弱。不写成正在等待盘中数据。

### 4.3 统一事实与观点

| 对象 | 必需内容 | 防止的问题 |
| --- | --- | --- |
| 事实 | 标的／板块标识、指标、值、单位、口径、报告期、数据时点、来源、版本 | 同名指标不同口径被混用 |
| 时间 | `event_at`、`published_at`、`first_seen_at`、`fetched_at`、`as_of` | 公告报告期当作可知时间、后验数据进入回放 |
| 观点 | 维度、结论、支持事实、反对事实、待核事项、改变判断的条件、生成时间 | 摘要无证据、模型编造观点来源 |
| 关联 | 证券代码及市场、主题／指数代码、成员映射版本、批次、决策标识 | 同名公司或近义题材错配 |
| 血缘 | 输入事实哈希、规则／提示词／模型版本、生成状态 | 无法复现，旧观点被包装为最新 |

报告期与公开可知时间都存在时才允许历史研究引用；只知道当前抓取时间的数据，不反向补成过去已知。模型观点仅引用白名单事实编号，不能编造引用或把未取得的一致预期填成“符合预期”。

### 4.4 档案与索引

- 优先复用 `feature_store.py`、结果索引、`runtime/state.py` 的既有记录，以只读聚合建立档案索引；不新增数据库产品、消息总线或向量库作为第一版前提。
- 索引按标的、研究批次、维度、事实截止及正式计划标识关联。跨批次研究观点可分别展示，必须显式注明其日期；不得把另一天的模型意见拼进本批资格判断。
- 正式发布仍引用现有 `console-truth.ts` 的精确匹配规则；找不到记录不等于证明从未发布。
- 单股聚合查询按需加载，不读取整份大研究 JSON 返回给浏览器；摘要、证据列表、时间线分页。
- 如确需新增持久化表，先盘点现有字段缺口，再做向后兼容增量迁移及中断恢复测试；保留旧数据，不先破坏性改表。

## 6. 研究字段补齐的具体口径

| 能力 | 第一版复用 | 后续需补充／验证 | 不能伪造或混用 |
| --- | --- | --- | --- |
| 盈利模式 | 现有主营拆分、公告页码及业务匹配 | 产品／地域／行业贡献、盈利驱动变化 | 题材名字不能证明收入占比 |
| 财报拆解 | 已有营收、利润、现金流及报告期 | 扣非、毛利、应收、存货、单季与累计勾稽 | 累计同比不当单季同比，非经常收益单列 |
| 估值 | 当前可核验估值及口径 | 历史价格与当时财务构成的点时估值序列、窗口、样本数、分位算法 | 不用当前财务倒算过去估值分位；负利润不强给 PE 排名 |
| 同行比较 | 已确认行业／产业链成员 | 同期、同合并口径、同单位财务及估值 | 不因概念标签相同即当可比公司；样本不足写不足 |
| 业绩预期 | 有时间和来源的明确预告／公开观点 | 可取得的历史预测及修订 | 无可靠一致预期时写“无法判断是否达预期”，不能用同比替代 |
| 题材定性 | A1 主营证据＋A2 阶段／角色 | 催化事件链、兑现与反证时间线 | 媒体热度不等于基本面兑现，市场周期不等于个别题材周期 |
| 板块指数 | 源榜单、成员、行情与本地指标 | 稳定成员版本及方法说明 | 无法取得专有强度时展示自有指标名称，不冒充原强度 |
| 宏观行业 | 既有政策包及来源 | 行业盈利、价格、产能及传导的定期增量 | 不把宏观方向直接写成个股业绩事实 |

免费源策略：先核验项目现有通达信、腾讯、东方财富及公告／公开宏观适配器的实际返回能力。当前未取得或需付费的数据作为明确缺口，不将付费同花顺接口作为交付前置；免费源间口径不同只做交叉核验，不静默混成一个指标。

## 7. 研究档案交互明细

本节使用 Impeccable 的规划方法，仅明确结构与状态，沿用现有青绿浅色终端、字体、密度和语义颜色，不进行视觉世界替换。

### 7.1 使用者与成功任务

主要用户仍为项目所有者，在盘前、盘后研究以及盘中查看既有计划。首要任务是快速回答：为何关注它、哪些维度支持／反对、数据到何时、现在有没有正式计划、还在等什么。

### 7.2 页面信息顺序

1. 顶部：名称代码／指数标识、选定研究批次、事实截止、证据状态；研究结论与正式执行状态分开。
2. 结论条：支持点、风险／分歧、下一步条件。不是统一“积极／买入”标签。
3. 三分区：先看风向、这家公司、行业罗盘；财务对比优先用表，观点使用短段落，来源可展开。
4. 技术计划区：三策略适用性、唯一当前路由、必要条件与数值、独立背景风险、A4 待确认；无正式计划时明确说明。
5. 历史区：研究版本变化、发布与失效、A4 事件、A5 归因、T+N。查看历史应固定历史截至时间，而不是默认混入今天的证据。

三个分区是信息组织，不代表缺少任何分区就无权研究。指数页面把“这家公司”替换为“这个指数／板块”，呈现编制／聚合口径、成员和集中度，不显示不适用的公司财务。

### 7.3 状态与内容规模

| 情况 | 页面行为 |
| --- | --- |
| 有档案、未入 A1 | 展示线索与研究状态，明确不属于正式执行候选 |
| A1 支持、A2 观察、A3 无买点 | 三个结论同时展示，不合并成“股票被淘汰” |
| 事实缺失或过期 | 精确到字段／受影响观点，旧观点保留日期，不用整页正常掩盖 |
| 来源冲突 | 并列冲突值与口径、采用依据或待核状态 |
| 仅量化结论、未送模型 | 标明量化生成，不写成专家已复核 |
| 模型解释生成失败 | 继续显示已有事实和量化判断，显示本次解释失败，不取消现有执行资格 |
| 空、加载、部分失败 | 分区加载与错误隔离；重试不触发研究全量重跑 |
| 多期财报、多主题、多条事件 | 折叠、筛选、分页；不复制全量日志入页面 |

桌面保持三分区锚点和证据抽屉；移动端单列及可展开表格，返回研究列表保留筛选和滚动位置。键盘可打开来源、关闭抽屉并返回触发元素；所有状态带文字，不能只靠红绿判断。

## 8. 调度、性能与磁盘约束

### 8.1 更新安排

- 月度：更新 A1 方向与基础研究版本；周度：更新方向证据、财务／事件变化和成员。
- 事件：仅对受影响股票、主题和观点发起增量任务；重大风险更新保留发生及已知时间。
- 每交易日：A2 冻结前百、板块和资金事实；A3 更新收盘技术条件。任务具体时间沿用生产调度，实施时核验，不在方案中盲设新 cron。
- 盘中：A4 使用既有正式计划和实时数据；档案读取、历史补齐和新增解释不得抢占盘中关键任务资源。
- 盘后：A5 和 T+N 任务幂等回填；延迟数据明确待补，不把未到期样本记零收益。

### 8.2 初始工程验收目标（非当前实测能力）

- 相同事实、规则和提示词版本的档案查看不产生模型调用；重复增量任务不产生重复计划、重复观点版本或重复通知。
- 首屏只返回摘要，单股摘要响应目标不超过 200 KB；证据详情分页。样本环境记录接口 P50/P95，暖缓存摘要 P95 初始目标不超过 2 秒，达不到时给出瓶颈，不隐瞒。
- 记录阶段耗时、排队时间、模型调用和重试；新增只读档案不应使同输入 A3 产生额外模型调用。
- 原始事实去重存储，档案引用原件；不要每股复制整份快照。记录每次增量的字节增长与保留策略，避免重复大 JSON 把虚拟机磁盘占满。
- 历史回放、证据补齐限并发、有界重试；触及资源保护时停止非关键补齐，不能通过删除生产原始证据腾空间。

### 9.2 档案与数据测试

- 新闻、公告、财报跨日期；当日晚公布的信息不能进入当日下午的历史判断。
- 估值分位不足一年、负利润、不同比较期、样本缺失：按实际可用范围展示，不硬算。
- 父子板块重复、多概念成员、同名异码、映射变更：排名、成员、去重均可追溯。
- 前百不足 100、重复名次、交易日错位、源失败：不能伪装成同日完整前百；趋势通道可独立呈现自己的质量状态。
- 模型引用不存在事实、修改服务器价格、把观察升为合格：校验失败，不进入正式发布。
- 观点有反证、存在来源冲突、无数据或解释失败：页面能呈现这些真实状态。

### 9.3 执行与表现回归

- A3 的观察、缺口、否决及未知状态永远不能因新展示字段进入发布；正式计划发布仍由原权威链决定。
- 原有 A4 条件、风控、止损和失效不变。涉及契约消费者时，使用固定输入验证动作与首要原因；未经验证不得称“盘中稳定”。
- T+N 按交易日历推进，停牌、除权及价格口径明确；研究收盘收益、信号后表现、模拟成交收益分别统计。
- 同一股票多批次／多计划按唯一事件标识去重；未成交不计成交收益。保留观察与否决负样本，避免只看成功者。
