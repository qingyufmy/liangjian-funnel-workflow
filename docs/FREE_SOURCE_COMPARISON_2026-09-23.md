## 结论

它的价值是免费入口发现、数据格式知识和按能力测试的思路，不是已经证明比我们全链路更可靠的取数框架。我们已有原始披露、覆盖账本、参考缓存、来源治理和冻结事实，不应另造一条绕过证据门槛的生产链。新源先旁路，原有入口发现的完整性缺陷直接补反例修复。

1. 通达信 `https://www.tdx.com.cn/products/data/data/g4day/20260922.zip` HTTP 200，2,742,225 字节。SHA256 `0680b353c39df70eec044f2796252413a0165825dcc9035bc156c94cb292ce28`。沪/深/北分别27,472/24,296/384条**证券**记录，并非A股数量。

3. 腾讯同日未复权日线独立请求：三只股票开、高、低、收全部一致。通达信成交量为2,457,294 / 75,945,732 / 16,205,533股；腾讯手数乘100为2,457,300 / 75,945,700 / 16,205,500股，差6 / 32 / 33股。表现为腾讯手数精度差异，但三样本不足以确立全市场容差规则。
4. 新浪 `CompanyFinanceService.getFinanceReport2022` 贵州茅台利润表返回2026-06-30、2026-03-31两期，每期77字段，披露日分别2026-08-15、2026-04-25。不能把今日接口返回的修订数字倒推成历史时点已知值。单位逐字段待对原报，不能将每股收益、比例等统一标元。
5. 巨潮 `https://www.cninfo.com.cn/new/data/szse_stock.json` HTTP 200，592,292字节。可访问不代表身份映射全市场完整，也不代表对该数据的再分发授权。

冻结证据位于本隔离工作树 `artifacts/source_audit/`：原始ZIP、哈希校验JSON、新浪原始响应和归一化结果、腾讯三个样本原始响应。未覆盖生产文件，不提交整包市场数据到公共仓库。接口可访问与数据再分发许可是两回事；两个新候选源的正式许可/运行环境覆盖验收仍未完成。

## 不吸收或尚不能承诺的部分

- 不使用猜测的orgId，不将HTTP 200等同业务成功，不把空响应当全量为空。
- 不把文件下载时间/Last-Modified当交易所时间或历史披露时间；不把不同腾讯域名当独立源。
- 不把新浪数值补齐当主营证据补齐；现有主营缺口仍需巨潮原文和分部口径验证。
- 参考项目关于通达信TCP行情失效的判断不是我们环境的探测结果，不能据此关闭当前通达信能力；应分日线、分钟、财务等能力分别检查。
- 不复制“请求一次、取前30条”式公告查询替代现有分页和可追溯证据。

## 下一步生产准入标准

1. 使用正式全市场股票目录运行盘后包旁路，记录逐股缺失、停牌/新股解释、OHLC冲突、单位差异；不要按代码前缀硬猜范围。
2. 在虚拟机做同日样本可达性和延迟验证，多日观察包发布时刻。首次接收时间独立落盘；缺包不阻塞原有日线源。
3. 新浪三张表选择盈利、亏损、银行、保险、新股样本，与原始报告逐字段核实金额、比例、每股单位、母公司/合并及修订版本。只有通过对账字段才进入既有A1覆盖账本，不能提升未经核实的feature_ready。
4. 全量探针接既有ProviderRegistry/ProviderGovernor和RuntimeStore配额、截止时间、故障账本，禁止把本轮手动采样脚本加入定时任务。现有侧车配置仍enabled=false；无需为手动离线解析创建伪授权注册。
5. 通过上述证据后再评估正式增量补采。不得以提升候选数量代替提升质量。
