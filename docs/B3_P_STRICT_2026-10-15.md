## 声明式转换

1. **原 A3 → normalized**：调用现有 `_plan_payload` 和 expiry 规范化，严格字段白名单和 old/new 哈希逐项对账，不允许任意新增字段。
2. **normalized → A2 authority**：绑定实际 A2 审计行（或已封存快照中的 A2 context）；selector / symbol / lane / snapshot / output_hash 和现有路由函数都必须成立。没有 authority 时，权限新增/改写仍失败。
3. **独立 shadow → submitted**：只能增加或精确替换 `strategy_facts.shadow_inputs`；实际独立投影必须原哈希相符、schema 正确、`execution_authority=false`。这只证明发布添加的内容，不证明影子算法获得执行资格。
4. **submitted → DB published**：两份实际对象必须完全相同；DB 结果不同即 `POST_PUBLICATION_PAYLOAD_CONFLICT`。不能从最终 payload 倒推一个“合理”原对象。
5. reader hook 再比较原 raw / final payload / run_id / lane_id / plan_id。缺原证明继续 DATA_LIMITED；默认 reader 路径未改。

## 主代理接线要求（本子任务不改 workflow）

`_publish_plans` 当前顺序为 raw normalize → A2 权限 → expiry → independent shadow → publish batch。expiry 与权限键分离，适配器 normalized 必须捕获为 `normalize_publication_expiry(_plan_payload(raw), candidate.expires_at)`，不得从最终 payload 去掉几个字段反推。

```python
# 同一调用、持久化之前捕获，而不是从未来 DB 重建：
originals = PublicationInputs(
    run_id=result.run_id, lane_id=lane.lane, plan_id=plan_id,
    a3_audit=bound(actual_a3_stage), raw_plan=bound(raw),
    raw_plan_location=(pool_name, raw_index),
    normalized_payload=bound(actual_normalized),
    submitted_payload=None, published_payload=bound({}), changes=(),
    authority=actual_selected_authority_proof,
    snapshot_chain=actual_snapshot_proofs,
    target_trade_date=candidate_expiry.date(),
    server_expires_at=candidate_expiry, published_at=now,
    publication_mode="CLOSE", minimum_trade_date=minimum_trade_date,
)
# shadow 是 shadow_inputs_for_publication 实际返回值的独立 BoundObject。
# submitted 是传给 publish_plan_batch 的 payload；published 是 DB 返回原行。
inputs = capture_publication_projection(originals,
    shadow_projection=bound(shadow), submitted_payload=bound(submitted),
    published_payload=bound(published))
receipt = PublicationReceiptBuilder().build(inputs, calendar=calendar)
```

必须保留的原始 freeze refs：本批 summary/audit 路径与文件 SHA；A3 stage 完整 output 与 output_hash、raw pool/index；实际被选择的 A2 stage/行 selector（或 snapshot context selector）；base 的真实快照文件字节 SHA/canonical hash，每层 overlay 的真实当时 recipe（详见续作，不伪造不存在的 overlay 文件）；独立 shadow 原结果哈希；submitted/published 对象哈希；run/lane/plan identity、目标交易日、发布时刻和服务器到期列。

**Reader 接线不得仅信 self-pinned envelope**：从本批 pinned audit 取原 A3/A2 stage，而不是相信封包自带副本；snapshot_chain base ID/hash 对照 summary/run，末端 snapshot ID 对照 A3 audit；selector 实际成员关系由 builder 再验。只有 `validate_projected_payload(...)["evidence_complete"] is True` 才可解释已证明的 payload 变化。overlay 没有真实生成 recipe 时保留 `AUDIT_OVERLAY_BINDING_UNPROVEN`，不能靠 ID 后缀推测 hash。

`encode_projection_inputs / decode_projection_inputs` 是本地 fixture/评审搬运入口。生产不得把 140MB 快照再次嵌入 summary/逐计划 payload：复用原冻结文件与 hash refs，读取 refs 后组装 `PublicationInputs`。封包 SHA 不是 acquisition/authenticity 证明，`decode` 保留原对象 hash 不会重新封印篡改对象。

## 卡片绑定

`card_plan_binding` 仅接受实际传入的完整计划行目录。plan_id 必须是 `source_run_id:lane_id:logical_id`，主题/纯 symbol/其他 run 或 lane 均失败；分页必须是完整目录的逐行原件子集；展示 symbols 与该页计划 symbol 顺序完全相同。返回绑定 rowset SHA 与 binding SHA。

绑定异常不改变客户投递正文或阻塞旧投递路径，而是 `DATA_LIMITED` 并保留固定原因；绝不使用 symbol/theme 补造 plan_id。summary 的 plan_ids 与封存卡上的 plan_ids 同值。旧卡片不回填。

## Reader 续作：独立 pin 与真实 recipe 链（12:52）

`PublicationReference` 新增默认 `projection_manifest: FilePin | None = None`。无 manifest 时原严格路径逐项不变；不得把普通业务发布当作严格证明。提供 manifest 时：

- 固定 schema `publication-projection-manifest/1`；manifest 自 hash 只校验完整性，同时要求 summary 的 `plan_publication.projection_manifests` 按 lane 精确唯一匹配其路径/文件 SHA（兼容单 `projection_manifest` alias），并与同一 pinned audit 对账。
- base FilePin 只读取/解析一次，ID/hash 对照 summary，summary 再对照 workflow_runs；audit 内 A3 唯一原 stage 提供 raw pool/index/hash；A2 唯一原 stage 提供 selector/value/source hash。不得由 DB final payload 反推这些原件。
- StageAudit 独立 `snapshot_proof` 的 schema 为 `research-snapshot-proof/1`；其真实生成 chain 节点为 `research-snapshot-recipe/1`。每个节点先验父 ID/hash/as_of，再核 hash_recipe，再按白名单 transform 核 data_recipe，最终 ID/hash/as_of 必须等于实际 stage 的封存值。
- 仅 base 为 `SnapshotProof.representation=ORIGINAL_FILE`；overlay 为新增明确合同 `PINNED_RECIPE`，必须确为该 pinned StageAudit 的 chain 成员，`file_bytes/file_sha256` 均为空，回执明确 `original_file_available=false` / `PINNED_CURRENT_RUN_RECIPE`。这是当时 recipe 的本地重建证明，不是补出的原文件，也不提高 acquisition authentication。
- A2 的新闻/轮动分支与 A3 的技术分支独立共用同一 base：`PublicationInputs.authority_snapshot_chain` 明确证明 A2 权威来源，绝不伪造 A2→A3 串链。
- 新增精确 `A2_STOCK_NEWS` transform，原 hash 口径不变；只允许它的实际采集 as_of 在父时刻之后且不晚于**实际发布封印时刻**。研究 `source_asof` 不冒充发布时间。普通 overlay 仍必须 as_of 相等。
- `A2_ROTATION_POLICY` 必须用真实原 board 重跑现有纯 authorized policy 并对账其 hashrecipe；`UNKNOWN_WRAPPER / SCOPE_RESTRICT / UNPROVEN` 不因标签 CAPTURED、相似 ID 或 final row 而放行。
- reader 每批共享 builder，base 文件只读一次；链 JSON 解码按原件 identity/hash/recipe 缓存。每个计划 seal 仍重算原对象哈希；文件 SHA 在生成结果和最终封印时再次核验。缓存不能掩盖原对象/文件变化。
- 成功计划增加小型 `publication_projection_receipt`，无 snapshot data/行情/模型文本；`eligibility_released=false` / `acquisition_provenance_authenticated=false` 仍保留。
