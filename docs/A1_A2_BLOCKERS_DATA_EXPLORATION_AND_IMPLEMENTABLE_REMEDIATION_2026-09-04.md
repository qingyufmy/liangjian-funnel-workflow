# A1 / A2 阻断项数据探查与可落地整改方案

## 1. 结论先行

截至 2026-09-04，本轮存在两个确定性阻断项和一个关联的运行时阻断项：

1. **801 精选板块源未真正接入。** 代码只有 `selected-board-YYYY-MM-DD.json` 的读取和校验器，没有采集器、授权接口或生产快照；当前 HiThink 公共接口只返回 881/884/885 分类，不能证明与手机端 801xxx“精选板块强度”同源。因此 A2 趋势通道没有可靠的“正净流入强度前五”入口。
2. **东方财富前100在 A1 与 A2 之间发生身份断裂。** A1 明确把合格的日度热门股加入当日有效池并标记可下游，A2 又通过 `DAILY_EMOTION_OVERLAY` 把它们定义成“非正式 A1 成员”，同时要求它们满足月度主营/瓶颈路线，导致情绪源被错误拦截。
3. **前一交易日结果没有在次日盘前前完成并激活。** 2026-09-04 08:30 的盘前任务显示 A1/A2 不可用，而 2026-09-03 收盘全量结果直到 2026-09-04 13:13 才生成。即使策略逻辑修好，缺少“前一交易日已验收结果”的原子激活门槛，盘前仍可能拿到旧结果或空结果。

这三项不能通过扩大 A2 数量、降低评分线或用其他分类榜代替来绕开。正确整改顺序是：**先接通事实源和集合身份，再修运行激活，最后做固定交易日回放和多日影子验收。**

本文件是方案和验收基线，不授权部署、数据库写入或生产任务重跑。

### 2.4 东方财富接口稳定性

现有适配器已经做了以下硬校验：同一交易日、必须恰好100条、排名必须为1—100、代码唯一、跨日缓存禁止冒充当日数据。

2026-09-04 对接口连续读取3次，三次均返回100条，前100成员和排名没有变化，请求耗时约275—487毫秒；完整内容哈希三次不同，原因是最新价等动态字段仍在变化。这证明：

- 接口当前可用，且完整性校验有效；
- “排名身份”与“动态行情内容”不能共用一个稳定性判断哈希；
- 日内前100会变化，系统必须固定收盘后采样时点，不能让月度池或次日计划随任意一次调用漂移。

该接口属于东方财富网页的实际数据接口，不是交易所正式接口。它适合作为情绪注意力源，但必须保留失败关闭、固定时点和独立异源验证。

## 3. 阻断一：801精选板块正式数据源

### 3.1 根因

缺失的不是一个字段，而是完整的数据产品合同：

1. 没有可调用的授权端点；
2. 没有板块全榜、强度、主力净额和父子关系的自动采集；
3. 没有选中板块在该交易日的成分股；
4. 没有日终冻结、哈希、质量校验和恢复告警；
5. 没有历史时点成分，无法保证回放不使用未来成员。

### 3.2 数据源决策

| 方案 | 能否作生产主源 | 优点 | 阻断/限制 | 结论 |
|---|---|---|---|---|
| 扩展现有 HiThink 授权服务，新增801同源接口 | 可以，优先 | 已有密钥、限流、错误处理和部署网络 | 供应端当前未暴露801；需要确认数据授权和字段语义 | **首选** |
| 同花顺 iFinD 官方 HTTP/SDK | 可以，备选 | 官方支持 HTTP、Linux、板块成分及指定日期报表 | 需要正式账号/refresh token；还须确认“手机精选板块强度、主力净额、父子层级”是否属于可授权指标 | **并行做可行性验证** |
| 操作员导出的同日完整 JSON | 只可应急/回放 | 可快速校验截图口径 | 依赖人工，无法保证每天15点后到位 | 不作长期生产主源 |
| 881/884/885、东方财富BK、腾讯广度推算 | 不可以 | 已有数据 | 与801不是同一分类和强度算法 | 只作异源核验 |

同花顺官方资料确认 iFinD 提供 HTTP 接口、Linux 支持和“板块成分及报表”，专题报表也支持指定日期取板块成分；HTTP access token 有效期7天，接口存在 QPS 限制。官方资料并没有公开确认手机端“精选板块强度/主力净额”的具体指标名，所以采购或接入前必须在超级命令/试用账号中生成并实测命令，不能仅凭“同花顺”品牌相同就认定同源。

官方资料：

- https://quantapi.51ifind.com/gwstatic/static/ds_web/quantapi-web/
- https://quantapi.51ifind.com/gwstatic/static/ds_web/quantapi-web/help-center/faq.html
- https://quantapi.51ifind.com/gwstatic/static/ds_web/quantapi-web/example.html

### 3.3 可实施的数据合同

新增 `SelectedBoardProvider`，供应端无论是 HiThink 还是 iFinD，都必须映射到同一个内部合同：

```text
trade_date
captured_at / provider_updated_at
provider_id / request_id / source_url
board_code / board_name
board_level: PRIMARY | CHILD
parent_board_code
strength
main_net_inflow_cny
constituents[]
provider_total_count
rank_hash / member_hash / content_hash
```

关键原则：

- 801代码是唯一身份，名称只用于展示；金刚石概念与培育钻石不得按相似名称合并。
- 全榜先按“一级板块、主力净流入大于0”过滤，再按强度降序取前5。
- 正流入子板块继承父板块排名，不额外占用前5名额。
- 只要前5一级板块或其入选子板块缺少成分，趋势通道失败关闭；不能用当前股票标签补猜。
- 每天冻结当日成分。若供应商只能返回“当前成分”，从接入日起仍要每日归档；历史回放只能使用当日已归档成分或供应商明确支持的历史日期成分。

### 3.4 采集时序

建议独立于 A1/A2 主任务执行：

1. 15:08 第一次获取全榜；
2. 15:12 第二次获取并比较 `rank_hash`；
3. 若两次一致，15:12 版本成为候选快照；若不一致，15:18 再取一次，以固定截止时点版本为准并记录“收盘后仍变化”；
4. 拉取前5一级板块及其正流入子板块的当日成分；
5. 通过完整性校验后原子写入 `storage/facts/selected_board/selected-board-YYYY-MM-DD.json`；
6. 最晚 16:00 未形成合格快照，发送飞书阻断告警，A2趋势通道保持关闭；情绪通道不受牵连。

不建议按请求重试无限等待。网络重试限定3次，分别采用短退避；业务数据仍不稳定时按固定15:18截面冻结，而不是继续追逐变化。

### 3.5 质量门槛

发布前必须同时满足：

- 交易日等于最近已收盘交易日，采集时间不早于15:05；
- `provider_total_count == 唯一板块数量`，无重复801代码；
- 每条都有代码、名称、强度、主力净额；
- 父板块存在，父子不能成环；
- 前5一级板块和被选中子板块的成分非空，成分代码格式合法；
- 全榜数量不得低于最近20个有效交易日中位数的95%；超过10%的日间突变触发警告但不单独修改榜单；
- `rank_hash`、`member_hash`、`content_hash`全部校验通过；
- 生产结果只引用同一快照ID，不允许排名来自15:08而成分来自次日。

首次上线还没有20日基线时，使用供应端返回总数完成性和人工核对清单，不人为猜一个固定板块总数。

### 3.6 飞书告警

复用现有通知投递账本和去重机制，新增以下中文告警：

| 原因码 | 中文告警 | 处置 |
|---|---|---|
| `SELECTED_BOARD_AUTH_FAILED` | 801板块数据授权失败 | 趋势通道关闭，检查授权/令牌 |
| `SELECTED_BOARD_SOURCE_UNAVAILABLE` | 801板块数据源不可用 | 有界重试后关闭趋势通道 |
| `SELECTED_BOARD_TRADE_DATE_MISMATCH` | 801板块交易日不一致 | 禁止激活快照 |
| `SELECTED_BOARD_RANKING_INCOMPLETE` | 801板块全榜不完整 | 禁止激活快照 |
| `SELECTED_BOARD_CONSTITUENTS_MISSING` | 前五板块成分缺失 | 禁止趋势池进入A2 |
| `SELECTED_BOARD_RECOVERED` | 801板块数据已恢复 | 只在首次恢复时发送一次 |

去重键使用 `source + trade_date + reason_code`，状态未变化不重复轰炸；恢复告警必须引用对应阻断事件。

## 4. 阻断二：前100情绪票的A1/A2身份断裂

### 4.1 根因

A1 的日度叠加逻辑做了正确的事情：

- 前100通过交易资格和重大风险硬过滤；
- 月度池已有的19只增加情绪标注；
- 月度池没有的79只新增到 `active_research_pool`；
- 新增股被标记 `status=ACTIVE`、`downstream_trade_eligible=true`。

A2 随后却定义：只要 `selection_basis` 或 `research_route` 等于 `DAILY_EMOTION_OVERLAY`，`formal_a1_member=false`。更早的路线评分还要求这些情绪票具有月度主营、供应链瓶颈和稀缺层证据，导致79只全部出现同一组资料缺口。

这是两个互相冲突的合同：A1说“属于当日有效池”，A2说“不是正式A1成员”。

### 4.2 正确集合

应明确拆成两个正交身份：

```text
A1月度趋势成员 = 月度方向 + 801成分 + 主营匹配 + 基本面合格
A1日度情绪成员 = 当日东方财富前100 + 可交易 + 无重大硬风险
A1当日有效成员 = A1月度趋势成员 ∪ A1日度情绪成员

A2趋势候选 = A1月度趋势成员 ∩ 当日正流入强度前5板块
A2情绪候选 = A1日度情绪成员 ∩ 情绪行为证据合格
```

情绪票不要求具备月度主营/盈利证据才能进入情绪观察和情绪周期判断；但它不能因此绕过停牌、退市、重大财务违法、不可交易、极端流动性和涨停结构风险。

### 4.3 字段改造

废除含义模糊的 `a1_formal_member`，新增：

- `a1_effective_member`：是否属于当日A1有效池；
- `a1_membership_kinds`：`MONTHLY_FUNDAMENTAL`、`DAILY_EMOTION`，允许同时存在；
- `trend_source_eligible`：是否具备月度趋势来源资格；
- `emotion_source_eligible`：是否来自同日完整前100并通过硬风险；
- `emotion_cycle_action`：允许试探、允许接力、仅观察、禁止新开仓；
- `a2_pool_channel`：趋势、情绪、双重、无；
- `a2_disposition`：聚焦、观察、资料待补、否决。

不能再从 `selection_basis` 的字符串反推集合身份。

### 4.4 A2处理顺序

每只 A1 当日有效股按以下顺序处理：

1. 校验 `a1_effective_member=true`；
2. 执行通用交易资格和重大风险硬过滤；
3. 分别计算情绪、趋势两个通道，不先做共用的月度业务路线评分；
4. 情绪通道检查：同日前100、首板/连板/换手承接/炸板、情绪周期、流动性；
5. 趋势通道检查：月度方向、801前5成分、主营披露、基本面、相对强度和资金；
6. 两个通道都不满足才进入资料待补或轮动外；
7. A3只能读取 A2 明确允许下游的通道，不读取普通观察/否决池。

当市场处于分化、退潮或冰点时，情绪源仍要完整保留，但 `emotion_cycle_action=仅观察/禁止新开仓`。因此修复后 2026-09-03 的27只日度补入情绪型股票不应被自动升级成27只聚焦票，而应与博云新材、思泉新材一样进入可解释的情绪观察层。只有在启动、确认或加速阶段且结构条件成立时，才有资格进入A2情绪聚焦并交给A3。

### 4.5 东方财富前100固定时点

月度与日度必须分层：

- 月度 A1 的753只封存，不因前100每天变化而回写；
- 每个交易日15:15形成一份独立前100收盘快照；
- 次日盘前和当日 A2/A3 均引用这份固定快照ID；
- A4盘中不刷新前100，不让候选集合在计划执行中改变；
- 同时计算 `rank_hash`（只含排名/代码）和 `market_content_hash`（含价格、涨跌、换手等），避免动态行情变化被误判为榜单身份变化；
- 抓取失败时，昨天榜单只可展示为历史参考，不可冒充今天情绪源。

这解决“月度执行/周度更新”与“前100每天变化”的冲突：月度池负责趋势和基本面稳定性，日度快照只负责情绪通道的当日覆盖。

## 5. 关联阻断：日终结果激活和次日盘前

2026-09-04 08:30 盘前任务拿到 `A1/A2 NOT_AVAILABLE`，而有效的 2026-09-03 收盘结果在 13:13 才完成；11:37 的 A5 午间仍引用较早的 2026-09-03 15:37 结果。这是“有文件”与“有可用最新结果”没有形成明确发布边界。

落地方案：

1. 每个交易日收盘工作流生成候选结果，但不直接成为下游最新结果；
2. 依次通过源完整性、A1/A2/A3集合、中文导出和 containment 校验；
3. 只有全部通过后，原子更新 `latest_accepted_close_run.json` 指针；
4. 指针至少包含 `trade_date`、`run_id`、`snapshot_id`、A1/A2/A3输出哈希、激活时间和验收状态；
5. 次日08:25预检必须确认指针交易日等于最近已收盘交易日；不一致则飞书告警并失败关闭A3/A4新计划；
6. A3为0只但上游完整时，状态必须是“已核验、无合格计划”，不能误报成A1/A2不可用；

## 8. 两轮方案复核

### 第一轮：业务口径复核

初版容易把用户关注的“液冷、金刚石、贵金属有色”直接写成原始榜前三。重新对照截图后确认：截图中的原始一级正流入强度排序与策略关注方向不是同一个概念。整改方案因此调整为两层：数据层完整保存801原榜和父子关系；策略层再叠加A1月度方向、催化和主营基本面。策略层可以关注贵金属/有色，但不得篡改或重命名原榜排名。

### 第二轮：工程与时点复核

初版只解决“今天能否拿到成分”，没有解决历史回放使用未来成分和次日盘前读取旧结果。方案已调整为：每日冻结点时成分；历史回放只能用历史成分；所有阶段绑定同一快照ID；收盘结果通过containment后原子激活；次日盘前强制核对最近已收盘交易日。

## 9. 剩余风险与需要外部确认的事项

1. **801商业授权。** 当前仓库和生产环境没有可用的 iFinD 凭证，也没有 HiThink 的801端点。需要供应方确认数据授权和字段语义；这一步是唯一真正依赖外部协调的阻断。
2. **历史成分可得性。** 如果供应商不提供历史日期成员，2026-09-03完整回放仍需当日官方导出；截图只有排名和资金，不能证明个股成分。
3. **移动端与iFinD字段一致性。** 即使使用iFinD，也必须用同日截图逐字段验收，不能默认移动端精选榜与任意iFinD板块指标相同。
4. **东方财富网页接口变化。** 当前接口可用但不是公开交易所契约；必须保留精确100校验、固定时点、错误告警和可替换适配器。
5. **情绪分类误差。** 修复身份只解决“能否进入正确通道”，不证明行为分类模型已完美；需在十日影子样本中核对首板、连板、炸板和换手证据。
6. **A3为0的误解。** 风险退潮或无合格买点时A3为0可以是正确结果；验收重点是三条路线都有候选与否决记录，而不是强行凑票。

## 10. 建议执行顺序与最终决策

建议按以下顺序推进：

1. 先向现有 HiThink 供应方申请801同源全榜和历史/当日成分接口；同时用 iFinD 试用或正式账号验证是否能取得完全相同字段。
2. 在接口确认前，可以完成 A1/A2 双身份修复、榜单/行情双哈希、告警和结果原子激活，但趋势通道继续失败关闭。
3. 取得接口后完成2026-09-03对账回放；没有完整成分证据，不发布所谓“修复后的趋势池”。
4. 连续10个交易日影子验收；通过后再决定提交、推送、部署和生产切换。

最终目标不是让 A2 数量看起来更多，而是让每只股票都有正确来源和去向：情绪票来自同日完整前100，趋势票来自月度基本面池与801正流入强度前5；两条通道都能追溯到 A1，A3只接收A2明确允许下游的对象。
