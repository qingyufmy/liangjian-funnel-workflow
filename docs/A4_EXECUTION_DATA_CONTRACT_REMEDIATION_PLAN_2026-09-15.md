# A4执行数据口径统一：修复与验收方案

日期：2026-09-15。此文保留最初方案及验收标准；盘后已分批实施，实际测试/发布及未完成项以 `POST_CLOSE_REMEDIATION_2026-09-15.md` 和 `A2_STRUCTURE_A4_COMPLETION_2026-09-15.md` 为准，不能将下述方案审查当作全部实现验收。

本方案补充并约束《A4_MINUTE_ALERT_DIAGNOSIS_2026-09-15.md》。当日运行事实沿用该报告14:02截止的只读证据，不代表此后的实时状态。72组冻结窗口已核对时间和连续性，**尚未完成逐根OHLCV、全部策略及模拟订单差异验收**。

## 一、结论与必须纠正的表述

主要缺陷是校验、量化执行、模型上下文和告警使用了不同口径，不是策略门槛过严。不得以放宽买点、盈亏比、MACD/KDJ或行情新鲜度条件解决。

原诊断将原生五分钟源概括为“辅助源”不够严谨：当前量化主路径用一分钟聚合，但模型上下文仍用单独取到的五分钟；520历史预热和A5复核也有五分钟依赖。云南白药09:55可确认当时量化判断未被阻断，不能据此认定所有下游均不受影响。只有完成依赖迁移、确认所需历史完整后，才能将对应接口缺项准确标为辅助降级。

新增代码风险：`runtime/monitor.py`在读取持仓及检查硬止损之前，遇到行情错误直接结束该计划判断。因此完整入场窗口缺失可能同时阻断持仓风险评估。此为代码路径发现，**未证明今日发生漏止损或漏卖**。

## 三、唯一的时间与聚合契约

### 3.1 市场时间不等于供应商标签

深交所规定：开盘集合竞价9:15—9:25；连续竞价9:30—11:30、13:00—14:57；收盘集合竞价14:57—15:00。不能把整个下午都称为连续竞价，也不能从交易时段直接推定某接口使用开始标签还是结束标签。[深交所交易时间说明](https://www.szse.cn/www/investor/knowledge/stock/deal/t20191204_572383.html)

执行统一采用北京时间、结束时间标签、已闭合窗口；窗口函数接入交易日历及市场标识。当前沪深A股适配不得无证据扩展到其他市场或盘后固定价格交易。

| 检查时刻 | 应有的最近闭合5分钟 | 应有的最近闭合15分钟 |
| --- | --- | --- |
| 11:29:59 | 11:25 | 11:15 |
| 11:30—13:04:59 | 11:30 | 11:30 |
| 13:05—13:09:59 | 13:05 | 11:30 |
| 13:10—13:14:59 | 13:10 | 11:30 |
| 13:15 | 13:15 | 13:15 |

表中表示窗口理论闭合时间，不保证数据已在边界瞬间收到。13:02保留11:30五分钟是有效输入；若具体策略要求午后确认，则输出“等待13:05闭合”，并独立检查最新一分钟/报价。不得直接据此产生买入许可。

### 3.2 供应商适配与完整性

- 保留原始标签、开始/结束标签类型、标准化后结束时间、时区、供应商及适配版本。开始时间转换按该接口已验证契约实施，不统一机械加一分钟或五分钟。
- 通达信现有`_tdx_bar_end`包含13:00映射11:30的特定适配；不得推广到任意来源。若同批同时出现两个映射后同时间的记录，必须核对内容冲突，不能静默覆盖。
- 唯一键包含证券、交易日、周期、结束时间及数据版本。完全相同重复可去重；重复冲突、缺根、旧日、未来根、无法确定顺序均保留明确诊断。
- 不生成午休空K线，不前值填充缺根。五分钟/十五分钟桶必须由完整预期一分钟集合形成，不能仅凭根数凑齐。
- 对开盘竞价的09:30记录，确认其是否已并入09:31等记录；以成交量/成交额和供应商定义核对，不仅看标签。收盘竞价单独验证15:00发布及修订。
- OHLC按完整窗口首开、最高、最低、末收；成交量和成交额求和。成交量先统一为股，保留原单位及转换倍率；复权口径必须一致。
- 跨源价差按证券最小价格变动单位和接口精度逐项说明，量差先排除单位、竞价与截止时间差异；不直接设一个宽泛百分比把真实冲突放行。

## 四、统一执行包与独立复核

主链路：原始一分钟 → 版本化标准化与完整性检查 → 同一聚合器产生五/十五分钟 → 冻结执行包 → 量化、模型、告警和审计共同消费。

执行包至少包含：

- 证券、市场、交易日、策略/计划标识；市场计算截止时间、实际决策知识截止时间、冻结时间。
- 原始来源、请求起止及实际响应接收时间；供应商发布时间有则记录，无则明确未知。
- 标签约定、复权、价格精度、成交量单位、标准化/聚合/契约版本。
- 各周期理论末根、实际末根、缺失时间点、历史预热范围、内容哈希、上游版本引用。
- 新增仓就绪状态、持仓风险可观测状态、辅助复核状态、受影响策略及中文解释参数。

现有`captured_at`代表存储捕获时间，不等于网络接收时间。必须区分“14:00闭合，14:00:05收到并决策”和“14:02才补到14:00数据”；不能用`接收时间<=K线结束时间`这种错误条件拒绝正常发布延迟。

独立原生五分钟保留在复核通道。缺项且执行必需输入完整时可降级；实质性OHLCV冲突未解决时，按受影响策略阻断新增仓并记录调查证据。不得为了统一口径取消备用源，也不能声称当前失败的通达信节点已恢复。

## 五、数据状态、策略状态、持仓状态分别管理

| 数据状态 | 判定 | 处理 |
| --- | --- | --- |
| 数据正常 | 当前必需输入完整、有效且在知识截止前取得 | 继续策略判断；不代表有买点 |
| 等待闭合/发布 | 所需下一窗口未到闭合时刻，或处于经测量确定的正常发布期 | 等待；发布期内也不得使用缺失/未闭合根开仓 |
| 辅助源降级 | 执行输入及相关历史预热完整，仅独立辅助复核缺项 | 允许不依赖该缺项的计算；持续保留复核不足状态 |
| 执行数据阻断 | 必需窗口缺失、过期、格式不明或实质冲突未解决 | 阻断相应证券及策略新增仓，不无差别阻断其他证券 |

“数据正常但策略等待午后确认”应同时表达，不能将所有技术等待改写成数据等待。超过发布期限仍缺失须升级为真实数据阻断；发布宽限依据实际延迟分布和执行时效确定，当前不任意增加秒数。

持仓风控另行处理：

1. 先识别现有持仓及当日可卖数量，再评估对应风险输入可用性。
2. 完整入场历史缺失，但可信当前一分钟具备高低价时，仍可检查已有硬止损。仅有实时报价只能证明报价时点状态，不能等价替代一分钟最低价或证明盘中从未触线。
3. 当前价格也不可信时，标记“持仓风险暂不可观测”，明确提醒；不得伪造价格、信号或成交。
4. 需要多周期结构的退出规则仍须满足自身数据要求；硬风险处理不得由模型否决。
5. T+1、可卖数量、挂单和实际成交状态继续独立约束。当天买入不可卖时记录风险已触发/待可卖处理，不伪装成交或修改历史成交。

## 六、按窗口事件重试、恢复与提醒

- 事件键：证券＋来源＋周期＋窗口结束时间；另保留首次缺口的故障事件标识，把连续未恢复窗口关联到同一故障，避免每分钟重新发首次告警。
- 同键只允许一个在途重试；设置次数、单次超时、总耗时和失效时间上限。沿用有界批次预算，不阻塞其他证券，也不积压到下个窗口盲目重放。
- 格式冲突、旧交易日和午休未闭合不当作网络瞬态反复重试。仅对可恢复的迟到、暂态请求失败按规则退避。
- 首次故障、影响升级、确认恢复通知；不变故障低频汇总。每次都重新计算受影响的执行和持仓范围。
- 提醒包含缺少何周期/末根、影响证券和策略数量、是否暂停新增仓、持仓风控是否可用。不再统称“全部行情异常”。
- 恢复必须验证原缺口及必需输入恢复，不以接口一次返回成功或某个其他证券正常作为恢复证据。

回放使用相同冻结计划、策略/代码版本标识，并在隔离输出目录保存基线与候选结果。模型输入未变化时可复用已冻结模型输出；输入变化而无对应历史输出时，不得把复用旧输出称为新链路验收。可做独立研究调用，但必须标为非原历史模型决策，不写生产。

旧窗口没有真实接收时间的，只能证明原冻结选择中保存了什么，不能补造接收证据。新增无未来数据测试需用带接收时序的合成样本与修复后采集证据补足。

对午休72组，基线已记录正常技术等待，修复后预期主要改变数据状态和上下文来源；任何动作、订单或持仓差异都须人工核对因果，不能预先承诺差异为零。

## 八、实施顺序、发布及两轮方案审查

### 第一批：消除确定误报并保护持仓监控

统一会话时钟；按实际依赖区分状态；修正数据错误早退对持仓监控的影响；加入边界、真实缺根、持仓/T+1测试。若模型上下文尚未迁移，不得提前把所有原生五分钟错误降为无影响提示。

### 第二批：完成数据包、版本时序及端到端一致性

迁移量化和模型当前日窗口，保留历史预热与独立复核；完善接收时间、来源标签、冲突事件和有界重试；运行72组、三策略及订单差异验收。失败响应仅落必要摘要、首末回执与内容引用，控制磁盘增长。

发布须在上述测试和冻结验收后、非交易时段通过现有`deploy.sh`完成。检查实际部署提交、服务和次日计划，不能靠健康页替代业务验收；不要求为此次分钟口径修复重跑A1。下一交易日自然检查09:35、11:30、13:01—13:05、13:15、15:00，核对执行包、判断及提醒一致性。

第一轮审查（依赖与语义，已在本方案核查）：发现并纠正“原生五分钟全是辅助”的过度概括；补充模型上下文、520历史及A5复核依赖；增加持仓风险与新增仓隔离。未完成调用清单不得宣布全仓迁移完成。

第二轮审查（因果与可验收性，已在本方案核查）：将72组根数核对与OHLCV/策略订单验收分开；区分市场截止和知识截止；旧证据缺接收时间明确保留缺口；源修订和模拟模型调用不能覆盖原历史。两轮均为方案审查，不是实现测试通过。

剩余风险：免费源延迟与节点可用性、开闭盘竞价口径、历史接收时间缺失、实际交易日缺少某策略样本，需分别交付证据；修好误报不等于备用源恢复，也不保证每天出现买点。

最终标准：**完整数据不误拦截，真实缺口不误放行；量化、模型、告警对同一份数据给出一致解释；新增仓受阻不静默停止持仓风险监控。**
