## 1. 提示词问题（按严重度）

### P1 · A2 主体仍写"前五 ∧ 净流入为正"，靠代码末尾英文段"覆盖"
`agent_2_theme_sentiment_transport_v2.txt` 第 37、33 行仍是 TOP5 口径；`common.py` 在 system 末尾追加 "Legacy TOP5 wording … is superseded"。同一 system 内两条相反指令，模型按哪条执行不可控；A5 反例里仍出现"未匹配前五且净流入为正"的说法即是旁证。→ 直接改正文，删除追加段。

### P2 · 审查型提示词让"同意服务端"成为最安全答案（迎合的真实形态）
- A3：PASS 的定义是"冻结事实内部一致，没有发现额外硬风险"。但事实全部由服务端生成，内部一致是构造上成立的；同时模型能看到 `eligibility=QUALIFIED`、`met_conditions`。结论被锚定，审查退化为盖章。
- A4：反方向偏置——"关键数据缺失、冲突或无法核验时必须否决"＋"板块或市场急变"这类无阈值措辞，否决几乎没有代价，而误否决从不被记录。
- 两者共同点：模型的"正确答案"由提示词结构决定，而不是由新增信息决定。这不是迎合用户，是迎合框架。

### P3 · 违反自身"数值只来自确定性引擎"原则
- 共享前置第 3 条：一切数值由引擎完成；但 A2 要模型输出 `score_breakdown` 0–100 分项，服务端再按权重算 `theme_score` 并比对 MIN_THEME_SCORE——主题分实质是 LLM 主观打分。
- 共享信封要求模型填 `data_quality_score`、`coverage`、`evidence_confidence`——这些应由服务端计算回填。

### P4 · 设计好的反馈通道是空的
A1、A3 都有 `{{PRIOR_OUTCOME_FEEDBACK}}`，A1 还写了详细使用规则；但 `workflow.py` 对该键 `setdefault(missing)`，叠加 9-18 起 A2/A3 标签未落库，模型从未收到过任何结果反馈。

### P5 · A5 提示词是"补丁堆"
40 条编号规则＋两段附加说明，几乎每条对应一次历史误报（如"目录没有 A5V:SUMMARY 时禁止使用"）。用提示词修补输出错误，应改为 schema 约束＋代码校验；提示词越长，pro/flash 模型越容易顾此失彼。输入已 14.6 万字符。

### P6 · 小问题
- A1 写入了带日期的规则事实（"2026-04-07 短线交易新规"），违背"交易规则只从 EXCHANGE_RULES 注入"。
- A2 用独立 transport system，不继承共享前置的 F/D 纪律，两套纪律并存。
- 三个死文件未归档，后续易被误改或误接线。

## 2. 每个 LLM 的作用评估

判断标准：模型是否掌握代码没有的信息，以及是否有结果数据证明它的边际价值。

| 层 | 模型独有的信息 | 当前作用 | 评估 |
|---|---|---|---|
| A1 | 政策文本、公告、主营披露、研报观点——代码难以结构化 | 主题映射、产业链节点、公司证据核对 | **最该用 LLM 的地方**。问题是没有反馈、没有命中率统计 |
| A2 | 新闻热度、题材叙事、阶段判断 | 阶段＋主观分项分＋少量 FOCUS | 中。阶段判断有价值；主观打分应去掉；今天 FOCUS 0 / WATCH 60，FOCUS 对下游影响有限 |
| A3 | 几乎没有——输入是结构化日线事实，代码已全部校验 | 只读核对＋否决 | **低**。被锚定的盖章；能用的只有事件日历/公告文本风险 |
| A4 | 几乎没有——分钟结构化行情；文本类风险（停牌、突发公告）少 | 触发后否决 | **低且有成本**：judge 段 p95 8.9s 占用 47s 预算；否决理由宽泛，误否决不留痕 |
| A5 | 对冻结事实的归纳 | 写报告 | 合适，但产出没有出口，提案不进入任何验证流程 |

结论：LLM 用在"读文本、找证据"上（A1、A2 的题材/公告）是对的；用在"复核结构化数字"上（A3、A4）基本是重复劳动，而且偏置不受控。

## 3. 改造方向：盲审 + 正反方证据 + 确定性裁决 + 结果校准

不论"JEV"具体指哪种做法，审查型 LLM 要去掉迎合，核心是四件事：

1. **盲审**：审查输入里去掉服务端结论（eligibility、met/unmet、QUALIFIED 等），只给事实与证据目录。模型先独立判断，再由服务端与确定性结论比对；一致/不一致都记录。
2. **正反方必填**：每个判断必须同时给出最强支持证据和最强反对证据（各 ≤3 条，只能引用 evidence_catalog ID），再给分类结论。只给一边即视为无效输出。
3. **确定性裁决**：模型只出分类（SUPPORT/OPPOSE/INSUFFICIENT＋证据 ID），是否否决、权重、阈值由代码决定；模型不再输出 0–100 分。
4. **结果校准**：否决和放行都记 T+1/T+3，按层统计"否决后实际上涨/下跌比例"。一个审查模型若否决组和放行组的后续表现无差异，就证明它没有提供信息，应降级为只读注释。

期望值（EV）不应该由 LLM 给：胜率和盈亏比只能来自标签统计，LLM 能贡献的是"这一笔和历史哪类样本相似"的证据归类。
