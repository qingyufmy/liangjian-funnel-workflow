# S10 分层评价与策略变更治理

## 已实现边界

`layered_evaluation.py` 只消费已有决策、结果标签和模拟订单的不可变导出，不生成行情、不重跑策略、不调用模型，也不写生产状态。它是现有 `outcome_labels`、A4 replay、replay window 和模拟账本之上的资格校验与成绩单投影，不是第二套回测引擎。

数据集必须显式选择：

- `AS_OBSERVED`：每条决策必须有冻结证据和真实 first-known 时间；任何证据缺失都阻断。
- `REPAIRED_DATA`：必须保存修复字段、原因和修复时间，报告固定标为不可声称历史可交易。
- `RETROSPECTIVE_MODEL_RESEARCH`：必须承认当前模型可能包含未来知识，固定标为不可声称历史可交易。

三类数据的 `run_id`、输入哈希和报告身份分开。未来收益标签可追加，但不会进入冻结决策身份。

## 预注册实验

预注册配置为 `config/evaluation_experiments.yaml`。固定层为：技术基线、加 A1、加 A2、完整 A3/A4、加模型否决。每层使用同一数据截止、交易资格、风险、成交与费用版本。所有层都输出，禁止只保存最好结果。

研究成绩单与账户成绩单分开：研究层记录候选与 1/3/5/10 日、MFE/MAE；账户层只统计真实模拟成交的费用后结果。阻断、跳过、未成交不算盈利交易。模型否决的信号影响与实际账户影响分开，禁止直接相加而忽略资金机会替代。

时间切分仅允许顺序 walk-forward，并按持有窗口做 purge、按预注册天数做 embargo。A1/A2 输入、通过、拒绝和缺失集合必须完整对账；未入围样本继续保留。券商金股若参与准入，不得复用为独立留出基准。

## 策略变更

评价结果和 A5 只能生成 `CONFIG_CHANGE_PROPOSAL`。提案必须包含假设、影响范围、冻结版本、训练/验证窗口、全部实验、对照、成本风险、验收门槛和回滚，且 `automatic_apply=false`。当前实现不修改生产参数。

## 当前证据边界

离线合成契约证明 EVAL-01—EVAL-09 和入口可运行，核心模块分支覆盖率为 98%。测试 fixture 只有一个样本，结果正确显示 `INSUFFICIENT_EVIDENCE`。尚未导入真实生产只读证据包，因此不能给出 `REPLAY_ACCEPTED` 或策略有效结论。
