# 迭代决策记录

## D-S00-01 隔离优先

所有开发在 `codex/implementation-s00-s11-20260920` 工作树完成。测试只使用临时 SQLite；离线 fixture 移除模型和通知凭证并阻断 socket。未授权前不部署、不 push、不触碰生产状态。

## D-S00-02 一个事实存储，不造平行平台

后续复用 RuntimeStore、A1 registry、分钟缓存、RiskGovernor、回放设施和当前前端投影。需要的新字段以兼容扩展或派生投影实现。

## D-S00-03 分级验收

代码通过不等于回放、运维和策略有效。`CODE`、`REPLAY`、`OPERATIONS`、`STRATEGY` 分开记录；缺少生产证据保持 `PENDING_PRODUCTION_EVIDENCE`。

## D-S00-04 不通过放宽策略制造改善

本迭代不修改策略阈值、不扩大候选数量、不降低数据完整性要求。easy-stock 只能作设计参考，新源默认旁路且无授权不启用。

## D-S01-01 观测是投影，不是第二事实库

状态继续以 `pipeline.outcomes` 为权威；只在同一契约中补充 `PARTIAL / TIMED_OUT / INTERRUPTED`。A4 观测写入既有 `latest.json`，不新增并行数据库。决策哈希排除墙上时间和耗时，来源尝试与版本仍保留可审计关联。

## D-S02-01 治理状态与事实分离

Provider 配额、并发、lease、尝试和 `last_good` 索引复用 `RuntimeStore`，只协调外部读取；公告、财务、分钟线等原始事实仍进入现有事实库和分钟缓存，不复制为第二套业务事实。注册项按能力拆分，同一上游包装器不视为独立验证源。

## D-S02-02 失败保持显式且有界

合法空集、未发布、鉴权失败、schema 变化、暂态网络、429、超时、时间不可证和口径冲突保持不同状态。只有完整、时间可证且资源限制内的 `OK` 响应更新 `last_good`；缓存过期时可展示但不能支持新开仓。

## D-S03-01 持仓保护优先且只有一个交易账本

持仓报价和硬止损在 A3 恢复及入场依赖之前处理，但实际意图、T+1、风险预算和模拟成交仍写入既有 RuntimeStore/PaperBroker。风险 lane 不建立第二账户或第二订单写入者；后续普通 lane 重复看到同一有效退出时由稳定事件键去重。

## D-S03-02 超时结果终态化，不杀线程造假

无法协作取消的依赖放入有限 daemon gate。调用者在绝对期限返回 `DEADLINE_EXCEEDED`，后台迟到结果不得修改旧决定；未结束 worker 持续占槽并让后续请求显式 `BACKPRESSURE`。辅助 5m 与反事实归档不占持仓/必需数据 gate。

## D-S04-01 覆盖账本是投影，事实仍只有一份

A1 覆盖行和补齐任务复用 A1 registry SQLite，仅保存字段资格、缺口和调度元数据；财务、公告及主营原文继续由既有事实缓存和冻结 snapshot 持有。覆盖率不以已收到记录作分母，失败对象不能通过删除获得更高比例。

## D-S04-02 新覆盖先影子诊断，完整性门槛只做显式原子门

新增证据契约当前为 `DIAGNOSTIC_SHADOW`，不修改正式 A1 策略门槛或候选数。只有 manifest 显式携带 blocking `coverage_gate` 时 registry 才拒绝激活；普通旧代次保持兼容。真实补采适配器未授权/未注册时 CLI fail closed，不把任务完成状态伪造成 packet 已修复。
