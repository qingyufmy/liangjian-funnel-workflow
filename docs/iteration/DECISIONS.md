# 迭代决策记录

## D-S00-01 隔离优先

所有开发在 `codex/implementation-s00-s11-20260920` 工作树完成。测试只使用临时 SQLite；离线 fixture 移除模型和通知凭证并阻断 socket。未授权前不部署、不 push、不触碰生产状态。

## D-S00-02 一个事实存储，不造平行平台

后续复用 RuntimeStore、A1 registry、分钟缓存、RiskGovernor、回放设施和当前前端投影。需要的新字段以兼容扩展或派生投影实现。

## D-S00-03 分级验收

代码通过不等于回放、运维和策略有效。`CODE`、`REPLAY`、`OPERATIONS`、`STRATEGY` 分开记录；缺少生产证据保持 `PENDING_PRODUCTION_EVIDENCE`。

## D-S00-04 不通过放宽策略制造改善

本迭代不修改策略阈值、不扩大候选数量、不降低数据完整性要求。easy-stock 只能作设计参考，新源默认旁路且无授权不启用。

## D-S01-01 观测是投影，不是第二事实库

状态继续以 `pipeline.outcomes` 为权威；只在同一契约中补充 `PARTIAL / TIMED_OUT / INTERRUPTED`。A4 观测写入既有 `latest.json`，不新增并行数据库。决策哈希排除墙上时间和耗时，来源尝试与版本仍保留可审计关联。

## D-S02-01 治理状态与事实分离

Provider 配额、并发、lease、尝试和 `last_good` 索引复用 `RuntimeStore`，只协调外部读取；公告、财务、分钟线等原始事实仍进入现有事实库和分钟缓存，不复制为第二套业务事实。注册项按能力拆分，同一上游包装器不视为独立验证源。

## D-S02-02 失败保持显式且有界

合法空集、未发布、鉴权失败、schema 变化、暂态网络、429、超时、时间不可证和口径冲突保持不同状态。只有完整、时间可证且资源限制内的 `OK` 响应更新 `last_good`；缓存过期时可展示但不能支持新开仓。

## D-S03-01 持仓保护优先且只有一个交易账本

持仓报价和硬止损在 A3 恢复及入场依赖之前处理，但实际意图、T+1、风险预算和模拟成交仍写入既有 RuntimeStore/PaperBroker。风险 lane 不建立第二账户或第二订单写入者；后续普通 lane 重复看到同一有效退出时由稳定事件键去重。

## D-S03-02 超时结果终态化，不杀线程造假

无法协作取消的依赖放入有限 daemon gate。调用者在绝对期限返回 `DEADLINE_EXCEEDED`，后台迟到结果不得修改旧决定；未结束 worker 持续占槽并让后续请求显式 `BACKPRESSURE`。辅助 5m 与反事实归档不占持仓/必需数据 gate。

## D-S04-01 覆盖账本是投影，事实仍只有一份

A1 覆盖行和补齐任务复用 A1 registry SQLite，仅保存字段资格、缺口和调度元数据；财务、公告及主营原文继续由既有事实缓存和冻结 snapshot 持有。覆盖率不以已收到记录作分母，失败对象不能通过删除获得更高比例。

## D-S04-02 新覆盖先影子诊断，完整性门槛只做显式原子门

新增证据契约当前为 `DIAGNOSTIC_SHADOW`，不修改正式 A1 策略门槛或候选数。只有 manifest 显式携带 blocking `coverage_gate` 时 registry 才拒绝激活；普通旧代次保持兼容。真实补采适配器未授权/未注册时 CLI fail closed，不把任务完成状态伪造成 packet 已修复。

## D-S05-01 完整分钟成交与实时报价风险观察分离

合成 quote 只用于当前持仓硬止损观察，不再扩展 high/low 或沿用累计 volume 证明模拟成交。订单只能由冻结、真实、已闭合且单位确认的一分钟线结算；同轮 quote 触发的退出意图保留到可用窗口，不能因等待数据而丢失。

## D-S05-02 next-minute-only 残单不秘密延寿

当前模型保持既有 next-minute-only 语义。容量不足时只成交可证明部分，剩余量记为 `PARTIALLY_FILLED_EXPIRED` 并释放预占；不在后续分钟偷偷追单。若未来引入多窗口订单，必须使用新 fill model/version 和独立成绩单。

## D-S05-03 测试费率与生产合同分离

费用测试使用总提示词指定算例；运行费率、最低佣金、其他费用、参与率和模型版本从 Settings/环境进入 broker 并冻结到账本。默认值只叫 `configured-paper-default`，不宣称是当前法规或用户券商合同；生产正确性需 OPERATIONS 对账。

## D-S06-01 风险预占与成交共用一个事务事实库

不新增第二套组合风控账户。委托先在现有 RuntimeStore 预占现金和风险，成交事务校验并消费该预占；明确失败释放，结果不确定则保留等待审计。这样并发、重启和迟到响应都不能绕过预算。

## D-S06-02 T+1 使用持仓批次，不用日期推测覆盖总仓

每次买入生成独立 lot 和 `sellable_from`，卖出按最早可卖 lot 消耗。账户级 `sellable_qty` 是批次投影；旧数据库仍保留兼容路径，但新成交必须有 lot。执行计划失效与持仓风险计划分离，不能因 A3 到期停止保护。

## D-S06-03 新组合阈值先留作影子参数

主题和组合开仓风险上限已能原子执行，但默认 `None`，不改变当前生产策略。生产启用前需要只读回放给出分布、拦截样本和增益，并单独授权；未知主题不会跳过计算，而是汇总到 `UNKNOWN`。

## D-S07-01 模型只有审核权，没有交易事实写权

模型输出只允许对冻结候选给出严格布尔否决、简短原因和冻结证据引用。股票、动作、价格、数量、交易权限和数据状态均来自确定性链路；出现任何越权字段、候选集合不完整或身份错配时整批阻断，不尝试猜测修复。

## D-S07-02 审核完整性和传输可审计性分离

业务响应绑定 `decision_id/snapshot_id/input_hash/deadline`；传输审计单独绑定模型和提示词版本并记录耗时、tokens/cost。客户端无法提供的计量保持未知，不以估算值伪装事实。模型不可用、超时与模型明确否决保持不同原因。

## D-S07-03 严格审核先暗接入，实验必须物理隔离

`strict_llm_review_v2` 默认关闭，只有完成回放和影子验收后才可申请启用。无模型和其他审核实验不得复用正式 RuntimeStore、账户 ID 或输出目录，避免实验结果污染订单、表现和通知账本。

## D-S08-01 展示语义随事实落盘，不在各客户端重新猜测

A1/A2/A3 阶段行携带版本化 `presentation`。API、Markdown、Web 和飞书优先消费该字段；旧结果只允许通过同一语义适配器转换。展示投影不授予交易权限、不改变策略阈值，也不回写原始事实。

## D-S08-02 未知不是零、不是安全、也不是可交易

缺少个股总分、覆盖率、证据时间、可卖数量或当前报价时一律保持 unknown/null。供应商总状态只作能力摘要，不能替代具体能力的新鲜度和覆盖；A3 合格仍必须等待 A4，固定R只作观察位。

## D-S09-01 新源只走并行旁路，不合并正式对象

旁路返回 `authoritative` 和 `shadow` 两个独立分支，禁止把影子字段补进正式候选、计划或订单。离线适配通过只叫 `ADAPTER_OFFLINE_TESTED`；没有真实授权和能力证据时保持 `LIVE_UNVERIFIED`。

## D-S09-02 来源身份和信息类型不可通过文本相似度互换

题材标签、目录概念、主营披露和行业分类使用不同 identity type。转载观点按原始来源链去重；HTTP 文件时间不等于交易时间。未来正式 fallback 必须同时通过许可证、上游独立性、PIT、覆盖和语义对照，并单独审批版本化配置。

## D-S10-01 评价只消费冻结账本，不重演历史事实

分层评价读取现有 decision/outcome/order 导出。忠实回放缺证据时失败，不从今天的数据自动补齐；补数和事后模型实验分别标记且不能声称当时可交易。未来标签可追加，但不能改写决策身份。

## D-S10-02 研究收益与账户收益永不合并

候选后续表现属于研究成绩单；只有真实模拟成交、费用和订单生命周期进入账户成绩单。阻断、未成交和被模型否决的信号收益不能直接叠加到账户结果，资金机会替代需要独立组合回放。

## D-S10-03 策略变更先提案后授权

A5、模型和评价工具只能生成完整 `CONFIG_CHANGE_PROPOSAL`，不能自动修改生产配置。少样本维持 `INSUFFICIENT_EVIDENCE`，不以年化或伪精确胜率推动参数变化。

## D-S11-01 生产证据由显式只读导出提供

验收工具不扫描虚拟机目录、不发现凭证、不连接外网数据库。操作者逐文件指定证据，manifest 保存版本、范围、哈希、缺项和脱敏说明；缺项返回 3，不以空文件或测试 fixture 升级验收等级。

## D-S11-02 数据库回滚不覆盖上线后的新事件

迁移只在一致性副本演练并保存 rollback 副本。生产上线后若已有新成交或状态事件，回滚优先撤功能、保留 additive schema 并前滚修复；不得用旧备份覆盖快照后的事件。

## D-S11-03 五日影子是运维门，不是收益证明

OPERATIONS 建议至少五个完整交易日且七类故障恢复齐全。终态率、数据可评估率和真实无机会率分开，全部阻断不能满足验收；即使运维通过也不推出策略盈利。
