## 给 Codex 的任务

你是本仓库的资深量化工程师、数据工程师、运行时工程师和测试负责人。请在当前实际仓库中，执行下面的分阶段改造，而不是只输出建议或再写一份计划。

最终目标有五个：

1. A4 在数据源异常、模型超时、重启及负载上升时，仍能在有界时间内给出可追溯的判断；持仓保护不等待与其无关的研究和归档任务。

**执行方式：读取当前代码 → 核实问题 → 写反例测试 → 最小修改 → 运行验证 → 更新证据和进度 → 进入下一阶段。**

- 不重写整个 `workflow.py`、`research.py` 或状态数据库；按职责逐步抽取，并通过旧入口适配到新实现。
- 不新增真实经纪商下单能力。保持 `simulation_only`、禁用外部订单以及现有人工复核约束；新增功能开关不得覆盖这些保护。

### G0.3 先核实，不能照着旧评审机械改代码

- 能复现的，先写失败测试再修。

- 仅在底层 API 存在的风险，不自动宣称生产一定触发；必须追踪真实调用者、传入对象和时间字段。

## S01. 统一状态、数据契约与运行可观测性

### 修改目标

扩展已有契约与投影，不再造第二个事实存储或并列“总状态系统”。旧字段通过单向适配保留；一个状态含义只能有一个权威计算入口。

### 数据与决策的基本维度

至少区分：

- 作业状态：`QUEUED / RUNNING / SUCCEEDED / PARTIAL / FAILED / TIMED_OUT / CANCELLED / INTERRUPTED`。
- 数据状态：`READY / MISSING / STALE / CONFLICT / NOT_APPLICABLE / UNSUPPORTED / PENDING_PUBLICATION / BUDGET_DEFERRED`。
- 机会状态：`PRESENT / ABSENT / UNKNOWN`。
- 交易资格：`ELIGIBLE / INELIGIBLE / BLOCKED_DATA / BLOCKED_RISK / PENDING_REVIEW`。

以上为语义目标，不要求与已有枚举完全同名；必须提供映射，避免同时维护两套可以矛盾的枚举。

每个可影响决策的数据对象，应能关联：对象/字段/周期、单位、币种、复权与成交额口径、提供方与上游来源、事实时间、发布时间、获取/入库时间、首次可用时间、快照/版本、原始内容哈希、完整性、降级原因、适用用途。共享元信息允许通过引用去重，不把同样的大对象复制到每条记录。

**用于历史决策的有效可用时间，不能早于发布、获取、入库和必要处理真正完成的时间。** 时间不可得时记录精度和限制，不用当前时间伪造旧的可用时间。

### A4 可观测性

逐轮记录以下 span：调度等待、计划恢复、市场状态、持仓报价、必需分钟线、辅助/归档、发布验证、数据库等待与写入、确定性计算、模型连接/首字节/输出结束、订单意图、模拟成交、通知。

每轮至少记录：

`run_id, decision_id, lane_id, scheduled_at, started_at, deadline_at, snapshot_ids, required_scope, ready_scope, blocked_scope, no_signal_scope, timing_spans, source_attempts, terminal_reason, git/config/prompt/fill_model/rules_version`。

用单调时钟计算耗时与期限，用带时区墙上时钟记录审计；两者不能混算。高基数字段保存在日志，不直接成为无界监控标签。日志包含来源和原因，但不包含 Key/完整 URL 查询秘密。

### 验收 S01

- `OBS-01` 同一外部失败在作业、数据、机会、交易资格上表达正确；“正常无机会”不是失败。
- `OBS-02` A2 存在非关键降级时，不能只给一个无解释的全绿色状态；关键/非关键覆盖及权限影响可见。
- `OBS-03` 所有结果、日志和错误分支带稳定关联 ID；隐藏秘密的测试用哨兵字符串验证。
- `OBS-04` 同一冻结输入重放产生相同决策哈希；实际耗时/记录时间可以不同，不参与业务决策哈希。
- `OBS-05` 耗时统计能从真实 span 算出 p50/p95/p99，不得写常量；缺数据时为 `NOT_MEASURED`。

1. 按 `provider + capability + account/quota_scope` 定义注册项，区分报价、分钟线、财务、公告索引/正文、市场宽度、题材，不将一个源的所有能力粗暴合并。
2. 记录支持字段、覆盖市场、单位/复权、时间精度、授权状态、速率/并发、TTL、过期动作、优先级、备用候选、原始上游身份。没有授权的能力禁止运行。
3. 复用已有持久化机制实现共享限流状态和有界 lease；重启不刷新配额。跨进程用短事务/原子操作，不在持锁期间做网络请求。长请求需要 lease 到期/恢复策略，不能永久占闸。
4. 相同能力、对象和快照请求合并；UI 轮询读取已发布数据，不发起额外全量抓取。请求合并不得把不同 `as_of`、权限、字段口径或数据范围混为同一次任务。
5. 有界重试：区分网络暂态、429、鉴权、schema 变更、合法空集、尚未发布。遵守 Retry-After 与配额，总重试受同一 deadline 限制。可用缓存不修改 last_success；失败结果不得清空 last_good 数据。
6. 失败冷却/熔断只用于减少无效请求；不得把故障静默转换成可交易数据。各进程共享状态；允许限量半开探测恢复，不形成惊群。
7. 备用源必须通过代码、交易日、周期边界、单位、复权、字段定义、时间资格与覆盖测试。保存备用选择原因及所有尝试。来自同一上游的两个包装器不能算独立验证源。
8. 对外请求限制域名与重定向、响应大小及解析资源；不允许从新闻/模型文本传入任意本地或内网 URL。避免借引入新源扩大 SSRF 与秘密泄漏风险。
9. Provider 返回时间戳用于证明数据时间，不能把 HTTP `Last-Modified` 或请求成功时间直接当作真实交易日/发布时刻；不能确证时标记 `TIME_UNVERIFIED`。

### 必测

- `SRC-01` 同一对象并发 50 个请求，远程抓取次数满足合并策略，结果无互相篡改；数字为离线测试负载，不是生产配额。
- `SRC-02` 重启后配额与冷却保留；主题和涨停池等共享 quota_scope 的请求不能各自绕过限制。
- `SRC-03` 上游依次 429、超时、恢复，退避与重试次数有界，之后恢复正常。
- `SRC-04` 合法空集、未发布、schema 异常、鉴权失败分别产生不同状态，不无限重试。
- `SRC-05` 坏响应不覆盖 last_good；旧缓存可展示，但关键新开仓读请求不能接受过期版本。
- `SRC-06` 备用数据单位/复权/日期冲突，拒绝替换并保留证据；合格备用可选择但不改写原始主源。
- `SRC-07` 源无响应或读取分片不断拖延，调用总时限仍有界，不仅是单次 socket timeout。
- `SRC-08` 过期 lease 可恢复，但旧 owner 的迟到写入不能覆盖新 owner，需 fencing token 或等价校验。

## S03. A4 稳定化：缩短关键等待链，隔离持仓保护

### 核心约束

本阶段改变数据准备与运行组织，**不改变既有策略条件**。同一合法冻结输入下，纯确定性策略的输出应保持一致；被修复的已证实缺陷需列入白名单并解释差异。

### 实施要求

1. **解耦生产者与消费者。** A4 正式决定只消费有来源、版本和有效时间的已验收快照。采集可以是同项目内独立任务/受控 worker，不要求引入消息中间件。保留现有 CLI/调度入口作为适配器。
2. **优先级与资源隔离。** 至少分为已有持仓风险、有效计划必需数据、辅助核验、失效计划/反事实归档四类。归档与辅助不得进入高优先级 `wait-all` 屏障，不共用会被低优先级耗尽的线程/配额/数据库队列。
3. **持仓保护单独调用。** 在可信报价就绪后，立即进入确定性风险评估，不等无关股票分钟历史、全市场刷新、LLM 或报告生成。已过期/退出 A1 的持仓仍保留冻结风险计划。没有可信当前数据时，只输出风险受阻与告警，不虚构退出价。
4. **唯一决策写入者。** 持仓保护和入场路径可并行准备，但订单意图/风险预算/成交仍走同一权威事务入口；同股票退出意图优先，防止两个 worker 一边卖一边加仓。
5. **取消批次耦合。** 健康股票可以在各自快照完整时进入评估，不等最慢的无关股票。若依赖的是共同市场状态，应等待该必需依赖或明确阻断受影响入场，不把其他股票的数据失效扩散。
6. **周期输入。** 1m→5m/15m 使用同一冻结的合格 1m 序列，不能跨午休拼接成错误周期。原生 5m 核验单独运行；其分歧是质量调查输入，不能隐式成为新的策略门槛。若分歧证明正式权威数据不可信，按正式数据冲突流程处理，而不是忽略。
7. **全局 deadline。** 调度轮开始即生成绝对期限，覆盖计划恢复、市场状态、抓取、快照、计算、审核和必要落盘；不能在慢任务之后另起一个“30 秒预算”。迟到回调不得修改当次已冻结决定或补发过期买单。
8. **真正有界等待。** 不能用 `future.cancel()` 假装能终止已运行网络请求，也不能退出时被 `ThreadPoolExecutor` 默认等待所有任务拖住。优先使用支持总 deadline 的客户端/协作取消；无法有界的依赖隔离到可回收工作进程，记录并限制泄漏 worker 数。
9. **队列背压。** 队列满时先推迟辅助、归档和重复任务。禁止为提升吞吐无界增加线程或放开所有 Provider 的并发。关键轮次不能悄悄漏掉：产生 `DEADLINE_EXCEEDED`、`BACKPRESSURE` 等终态。
10. **恢复。** 重启恢复持仓、未完成退出意图、计划身份、最近决策和有效 lease。历史缺口补齐后可恢复未来评估；补数不能伪装成当时已收到的实时数据，不追补过期入场。
11. **局部失败。** 股票级 Provider 缺口只阻断依赖它的路径；持久化一致性故障等系统级问题可全局阻断新增订单。辅助证据归档写失败不应自动导致核心账本失效，但必须保留受限记录/告警；核心快照无法持久化时不得新增正式订单。
12. **调用时钟。** 区分 bar_end、实际收到时间、策略截止时间、模型完成时间、订单最早生效时间。现有“上一闭合分钟”策略不能在重构时变成使用正在形成的 K 线。

### 必测

- `A4-01` 归档 Provider 永久阻塞，持仓风险仍在独立预算内输出，关键线程不泄漏。
- `A4-02` 原生 5m 很慢/失败，完整合法 1m 派生路径可继续；辅助状态正确。
- `A4-03` 同一 lane 一只股票缺数据，其他合法股票结果不受污染。
- `A4-04` 全市场状态慢/缺失，入场按依赖阻断，可信报价支持的持仓保护不等待它。
- `A4-05` LLM 超时，必要审核的新开仓不放行，已有持仓退出不受模型否决。
- `A4-06` 已到 deadline 的结果在边界前后到达，处理确定且幂等；迟到结果不能触发旧单。
- `A4-07` 正常、09:30/首个闭合周期、11:30/13:00 午休、14:45 入场截止、15:00、节假日、次日恢复按当前规则表处理。时间点依据实际生效配置核实，不重定义规则。
- `A4-08` 停牌/零成交/缺分钟不是同一状态，不以插值补全授权开仓；涨跌停不可成交证据正确限制模拟。
- `A4-09` kill/restart、重复调度、租约交接不产生重复订单或遗失持仓风险。
- `A4-10` 同合法输入的新旧纯策略结果一致；差异报告不能空跑或用结果总数冒充逐对象一致。
- `A4-11` 记录并告警可信报价已经过期的持仓，不能显示“风险巡检成功”。
- `A4-12` 验证隔离不止于网络线程：低优先级 SQLite 大写入不能长期阻塞风险意图的短事务。

### 性能验收口径

- 默认参考现有 D=47 秒与模型子预算，不将数字当成已达到的指标。新期限可配置，但不能靠增大 TTL 或 deadline 宣称修复。
- 离线假时钟用于证明截止逻辑；单独做有墙钟测量的受控压力测试，不将假时钟结果包装成生产延迟。
- 建立 50、100、200 个有效计划的压测 fixture，并按交易日历生成完整会话；这些是测试档位，不是生产股票数量上限。
- 第一版建议目标：在已验收数据就绪且无故意注入核心存储故障时，本地风险处理 p99≤2 秒、单轮调度有界完成≤D+小幅清理容差。记录硬件和负载；达不到时报告瓶颈，不伪造或自动放宽。
- 缺外部数据仍必须及时给出终态；“终态按时返回率”和“数据足够可评估率”分开统计，防止全 BLOCK 系统获得虚假的高稳定性。


## S04. A1 覆盖治理：把“数据不全”变成可补齐、可对账的任务

### 目标

在保留已有 A1 registry、事实缓存、特征代次和研究 packet 的前提下，建立字段级覆盖投影与增量修复调度。不是再建一个平行数据仓库，也不是把所有网络缺口交给模型解释。

### 覆盖账本

对每个 `symbol + capability/dataset + field + report_period/as_of + source_version`，至少能追溯：

- 是否应覆盖、是否适用、为何需要、供哪个研究问题或策略路径使用。
- 采集任务是否已排队/已请求、原始响应是否存在、解析是否成功。
- 字段是否存在、是否有限数、单位/币种/合并报表口径是否确认。
- 公告时间、有效可用时间、报告期及版本是否足以满足当前用途。
- 特征是否成功生成、属于哪个 feature generation、是否进入本次 A1 模型输入。
- 缺失原因、上次成功、最近尝试、下次尝试、失败次数、任务优先级和原始证据引用。

元信息可按数据集/对象继承，禁止机械地将每一层都复制成海量相同记录。底层事实保持不可变或版本化，覆盖账本作为可重建投影。

至少支持缺口原因：

`SOURCE_NOT_SUPPORTED, ACCESS_NOT_AUTHORIZED, NOT_FETCHED, BUDGET_DEFERRED, RATE_LIMITED, TRANSIENT_FETCH_ERROR, PARSE_ERROR, SCHEMA_CHANGED, FIELD_MISSING, REPORT_NOT_PUBLISHED, HISTORICAL_PERIOD_NOT_AVAILABLE, TIME_UNVERIFIED, STALE, CROSS_SOURCE_CONFLICT, FEATURE_BUILD_FAILED, PACKET_OMITTED, NOT_APPLICABLE`。

这些状态不要全部变成 `FAILED`。对证券生命周期等未成熟样本，区分“没有足够历史”与“接口故障”。已知负面数值仍然是有效事实，不属于缺失。

### 逐层对账与分母

固定输出各层对象集合及哈希：

```text
研究宇宙中应覆盖的对象/字段
→ 已请求
→ 有有效原始响应
→ 归一化成功
→ 通过来源与时间资格
→ 特征可用
→ 进入当前模型输入
```

每层集合差提供原因列表，而不只输出总数。`RAW_FOUND`、`PARSED`、`POINT_IN_TIME_READY`、`PACKET_READY` 分别展示。

覆盖率分母必须固定且版本化：

- 必需字段有效覆盖率 = 有效必需字段实例 / 当次适用的必需字段实例。
- 路径可研究率 = 满足该路径最低证据契约的股票数 / 该路径应评估股票数。
- 深度研究完成率、基础事实覆盖率分别计算。
- 不得从分母中偷偷删除采集失败股票；不适用项必须有明确规则和数量。
- 全市场/配置宇宙/抽样范围分别命名，不能用已收到记录数作为本该覆盖的总数。

### 最低证据契约

在现有配置中声明研究问题及其所需证据，而不是要求全部来源永远齐全：

- 多期盈利质量：明确报告期数量、报表类型、口径与公告时间要求。
- 主营/产业链暴露：公司资料、正式披露或可核验结构化证据；行业标签不等于收入贡献。
- 订单/政策催化：来源、发布日期、适用行业、受益机制和验证状态；观点仅是线索。
- 估值/预期：标明一致预期或券商观点，不与已披露事实混同。

保留现有正式判定的必要条件；新证据分级初期作为诊断/影子投影。不能为增加 ACTIVE 数量直接降低必需门槛。发现本身不可实现的原契约，提出能力变更提案并保留限制，而不是让模型凭空补全。

### 增量补齐与公平调度

1. 优先补实际使用的缺口：已有持仓研究、有效候选关键字段、过期的基础事实、其余宇宙；各类别须有配额与 aging，避免小票/后序代码永远排不到。
2. 使用当前 universe 版本和逐对象持久化任务游标；中断后继续未完成部分，成功项不因重启全部重抓。
3. 真实上游支持且授权允许时，优先公告索引/报告期批量发现，再对变化对象抓详情；没有批量接口时保留限速逐对象抓取，不能猜测并使用未验证接口。
4. 更新财报通过报告期/公告版本触发，辅以定期校验；不能仅以“抓取时间新鲜”代表财务内容最新。发现更正公告应追加版本，不覆盖历史。
5. 暂态失败指数退避和可配置上限；不支持/未授权字段不反复重试。未发布报告按日历与披露进度检查，不空转。
6. 记录计划量、完成量、延期量、积压最老年龄；能计算覆盖任务在当前配额下是否长期无法清空。不能仅把每轮成功率做高，却让积压持续增加。
7. 多来源补充禁止跨期间、跨币种、跨合并范围任意拼报表；财务摘要与原表应能核对且各有来源。
8. 研究宇宙基础层全覆盖；昂贵深度研究可分级调度。未深度研究者显示 `NOT_DEEP_REVIEWED` 等真实状态，不当作“已充分评估后淘汰”。
9. `a1_packet` 是完整事实的模型视图；原始材料不截断删除。重要风险和关键缺口即使长输入被压缩也必须保留可追溯摘要。声明全部覆盖时，逐股票/行业实际验证。
10. 活跃 A1/feature generation 使用完成度校验后的原子发布；新失败代次不得替代合格旧代次。沿用旧代次必须校验允许年龄及重大新风险，不把旧包永久标为最新。

### 必测

- `A1-01` 原始字段存在但解析映射错误，账本定位为解析/映射问题；修复后流入实际 A1 packet。
- `A1-02` 值为零、值为负、缺失、无穷/NaN、未授权、未发布和不适用分别处理。
- `A1-03` 合成 1,000 只股票、每轮最多刷新 100 只；稳定输入下多轮最终都被覆盖，新增高优先级任务不导致低优先级永久饥饿。数字仅用于验证公平性。
- `A1-04` 重启/失败恢复后只重做必要任务，成功数据不丢、不重复计数。
- `A1-05` 报告期早但公告实际晚于历史 cutoff，历史决策不能使用；后来的更正数据也不能回填旧决定。
- `A1-06` 仅有最新一期 F10 摘要时，不能产出“连续改善/完整三表已验收”；无正式发布时间时不得记为严格 PIT-ready。
- `A1-07` 财务负面为“有效但不合格”，采集失败为“未知/待补”，二者不混。
- `A1-08` 相同缺口运行两次不重复入队；已有 retry-after 不能被另一个 Agent 绕过。
- `A1-09` 改变模型输入压缩预算，关键风险和缺口不被消失；被投影掉的内容必须有范围/原因。
- `A1-10` 原始→特征→packet 集合数量逐层可对账，输入 821 或其他任意样本规模均不能出现无解释消失。
- `A1-11` 新代次中断、部分解析失败或低于发布门槛，不覆盖原活跃代次；过期活跃代次也不能伪装合格。
- `A1-12` 失败对象不从覆盖分母消失；“无适用字段”的组显示 N/A 而不是 100% 覆盖。

### 交付

实现可执行的 coverage-report / gap-report / backfill-plan / backfill-run 等价入口，提供 dry-run、scope、截至时间、重试预算、来源限制和输出目录参数。命令名可以合并到现有 CLI，但应文档化并测试。真实抓取默认不在离线测试中触发。

## S05. 修复模拟费用和成交因果性

### 前置要求

追踪真实运行与回放调用者。以下风险可能已在某些路径修复，先写能覆盖实际输入的反例；不能仅修改一个测试专用 `PaperBroker` 函数而遗漏生产调用路径。

### S05.1 费用引擎

将费用拆为明确组件：佣金、卖出税费、其他适用费用以及是否已经包含在佣金中。保存费用模型版本、交易规则/费率生效版本、计费基数和舍入方式。

- 最低佣金只约束佣金；不能将税费加进最低佣金的 `max()` 中。
- 测试参数不是生产费率。生产从当前配置和适用规则快照读取，不把本任务的数字当作法规/券商合同。
- 金额使用 Decimal 或整数最小货币单位及明确舍入规则；禁止浮点误差导致负现金或账不平。
- 部分成交按真实模型定义的计费单位处理。若按委托收最低佣金，则同一订单分两笔成交不重复收两次最低佣金；不同订单分别计费。
- 成交与撤单过程中保存已计组件、累计基数与调整，最终对账可重算。必须说明最低佣金在首次成交计收还是终结结算，确保临时账本与资金预占保守。
- 零成交无手续费；负数、非有限金额拒绝。费用不足时不生成现金为负的成交。

必须有独立算例：在显式测试配置“佣金 1bp、最低佣金 5、卖出税费 5bp、无其他费用”下，卖出 1,000 应为 5.5，卖出 10,000 应为 10，卖出 100,000 应为 60，买入 10,000 应为 5。同一订单两笔各 5,000 的卖出，总佣金 5、总税费 5；两个独立订单应分别应用最低佣金。

### S05.2 订单时钟与冻结内容

至少冻结：

`decision_id, trigger_episode_id, plan_id, signal_bar_end, data_available_at, deterministic_decided_at, review_completed_at, order_created_at, eligible_from, expire_at, order_type, limit_price, stop_basis, requested_qty, risk_reservation_id, fee_model_version, fill_model_version`。

`eligible_from` 不得早于所有必要信息及审核真正可用的时间。行情时间、策略时间和实际墙钟不能混用，禁止把分钟对齐后的时间当作真实审核结束时间。

### S05.3 撮合因果关系

1. 决策与初始数量只能用当时已知的信息。下一分钟 close/high/low 可用于之后的行情观察或合乎时间的撮合判断，不能反向改变开盘前已冻结的数量/ADD 盈利资格。
2. 已提交订单的剩余额度可按定义做成交前复核，但只能用复核时已经可用的信息，并保存取消/缩量原因；不能重算出比冻结数量更大的新单。
3. 若审核完成在一根分钟 bar 中间，只有分钟 OHLC 时，该整根 bar 的开盘和早先极值不能证明订单之后可成交。保守选择其后的完整合格窗口，或记为证据不足/错过时效。明确维持原 next-minute-only 到期规则还是增加新模型；不得偷偷延长订单寿命。
4. 有可信逐笔/盘口时，可按 `eligible_from` 后的事件顺序撮合；模型选择需显式标记，不得把两种粒度结果混在同一成绩单。
5. 收盘后出现的信号不能在先前收盘价成交；午休跨段需使用正式会话边界。
6. 使用下一根 K 线模拟限价成交本身不必然错误；错误在于使用订单生效前价格、未来收盘改变资格、或用不可知成交信息定量。
7. 合成 quote bar 不得伪装真实 1m OHLC 或成交量。使用合成数据必须有专门 fill contract；仅有一个报价时，不得以人为扩展 high/low 证明穿价成交。
8. 市价/保护性退出不得因为旧参考价不在下一窗口范围而无限等待旧价格回归；以真实可用且规则允许的后续成交价格处理。不可交易或缺证据时保留未完成退出意图，不能假装卖出。

### S05.4 成交能力与保守场景

实现按明确模型配置的可成交量上限、未成交、部分成交及残单处理。先用简单可审计参与率，不追求完整交易所排队模拟。

- 参与率分母使用真实可用成交量及已确认单位；累计量应计算窗口增量，不能重复使用整天量。
- 不把截至整分钟结束才知道的容量，记成已在该分钟开盘全部实现。分钟 OHLCV 的容量限制只支持窗口内估算，应记为窗口级模拟成交及其证据时间；需要开盘瞬间成交模型则必须有对应开盘流动性证据。
- 只有触价、没有队列证据时，保留既有保守规则或标记无法确认，不凭感觉提高成交率。
- 限价单不能因滑点高于买入限价；冲击成本要体现为不成交/部分成交或允许范围内价格，不能事后越价。
- 涨跌停、停牌、无有效量、竞价和临时停牌按当前规则/证据处理；无法证明排队成交时不能视为必成交。
- 输出基准/保守/压力情景及全部假设。它们是模拟估计，不是交易所真实成交。

### 必测

- `EX-01` 上述费用算例、最低佣金临界点、舍入、分单和部分成交全部通过。
- `EX-02` 固定决策输入、订单前账户及下一窗口必要撮合条件，只改变未来 close，冻结订单数量与先前资格不变；后续盯市盈亏允许变化。
- `EX-03` 10:00:00 收到信号、10:00:25 审核完成，不得成交在 10:00:00 或使用 10:00:25 前的价格穿越。
- `EX-04` 有/无精细时间证据、午休、闭市、订单到期分别产生明确结果；过期信号不得被补数激活。
- `EX-05` 容量不足发生部分成交，剩余数量与资金预占正确释放/保留；成交总量不超过容量。
- `EX-06` 独立验证主板/创业板/科创板等适用数量、tick、价格限制规则来自规则提供者，而不是靠写死代码前缀掩盖规则缺失；不支持证券明确拒绝。
- `EX-07` 买入后现金、费用、持仓、权益及预占可核对；并发两单不双花。
- `EX-08` 旧 fill_model 下历史记录不被新模型覆盖；修复结果是新的 replay_run_id。
- `EX-09` 合成 quote 和真实分钟线不会被错误地互换用于容量/穿价证据。
- `EX-10` 全部关键性质测试同时覆盖模拟 API 和实际 workflow→订单→结算的集成路径。

## S06. 组合风控、T+1、退出与订单生命周期

### 原则

使用现有 `RiskGovernor`、PositionRiskPlan、RuntimeStore、模拟账本扩展，不添加第二个“AI 风控官”。风险预算、预占、持仓、订单状态必须在同一权威账本上可对账。

### 必做工作

1. 核查已有单票/总仓位/风险单位是否在订单与成交两个边界一致执行。新增组合风险预算、主题集中、待成交预占的可配置约束。
2. 主题暴露使用冻结映射与明确分配规则；一只股票多个主题时说明采用主主题、分摊或最坏口径，不双重当作分散，也不对未知归属任意赋零。未知归属有独立保守桶或研究限制。
3. 组合开放风险要包含持仓和待成交订单。展示“到止损位的理论损失”与隔夜/跳空/连续无法退出的压力损失，不能宣称止损保证最大损失。
4. 新的主题、日损失、风险阈值先在影子配置中验证，不自动改正式策略。缺正式批准的阈值不能用示例数字代替；已有硬上限始终有效。
5. 资金/风险预占使用短事务与唯一 reservation/order ID；无网络或 LLM 调用在事务锁内。采用原子条件更新或单写入者避免两个 worker 看到同一剩余预算。
6. 同股票同时间多个策略路径竞争时，保存候选来源并由一个确定性冲突解析器决定，不重复开同一目标仓位。
7. 区分计划、触发事件、订单、成交、持仓五种身份。至少表达 `CREATED/PENDING_REVIEW/READY/RESERVED/SUBMITTED/PARTIALLY_FILLED/FILLED/CANCEL_PENDING/CANCELLED/EXPIRED/REJECTED` 等实际需要状态；名称可映射现有枚举。
8. 信号发出不等于成交；成交不等于全量成交；T+1 阻断不等于退出完成。未完成退出意图持久化，并在下一个合法机会重新检查，不重复记账。
9. 核查 `effective:{lane}:{plan}:{action}` 等去重键是否过粗，导致第二次分批减仓、撤单后重试或 T+1 后退出被吞掉。必要时引入 episode/order revision；只对同一业务事件幂等，不永久封死所有未来相同动作。
10. 新买锁定和已有可卖部分分别按 lot/session 追踪。加仓不把已可卖旧仓全部重新锁定。交易日释放依据真实日历，不因自然日变化或任务重跑提前解锁。
11. 计划过期只终止新入场，不终止持仓风险计划。风险计划应保存策略身份、冻结止损/退出规则、已用加仓次数、时间止损等。
12. 公司行动：复用已有逻辑处理价格/数量/成本/止损基准的等价调整，追加版本。无法核实公司行动时阻断依赖错误基准的新增交易并告警，不机械触发假损益；处理真实退出也需明确规则，不能无声撤销全部保护。
13. hard stop / sell / reduce / cancel / add / buy 的优先级在内存冲突解析与数据库消费端一致。任何 LLM 不得否决强制风险退出。
14. 退出重试基于当前可交易条件与可卖量，不能等待原参考价再出现；未知是否成交时必须先对账，不能盲目重下重复订单。

### 必测

- `RISK-01` 两个并发候选都单独合格，但合计超现金/总仓/主题/风险预算，只允许符合预算的原子结果，预占无负数。
- `RISK-02` BUY 与 FORCED_EXIT 同股票冲突，退出优先，不能同时增加风险。
- `RISK-03` 新买当日硬止损触发，记为受 T+1 约束的待退出，不记虚假卖出；下一合法交易日继续处理。
- `RISK-04` 旧仓可卖、新仓锁定，减仓只扣合法数量；重启不改变状态。
- `RISK-05` 同一成交回调消费两次，现金/持仓只改变一次；部分成交→重启→后续成交正常累计。
- `RISK-06` 未成交取消、到期和拒绝释放相应预占；部分成交只释放未成交部分。
- `RISK-07` 第一次减仓后新 episode 再次减仓可正常表达；重复同一 episode 不重复成交。
- `RISK-08` A3 计划过期/A1 不再覆盖，实际持仓仍受原策略风险计划管理。
- `RISK-09` 跳空越过止损、连续不可成交、跌停受阻，都不以理论止损价虚构退出。
- `RISK-10` 公司行动可核实和不可核实两种输入，数量/成本/止损/收益处理可追溯且无未来数据。
- `RISK-11` 账本事务前后崩溃恢复不半写；从事件账本重建投影与实际余额一致。

## S07. LLM 审核严格化、时限与可测增益

### 目标

保持正式通道原有权限，仅在确定性候选后进行有时限审核。将“返回合法 JSON”提升到“返回完整、对应当次候选且类型严格的审核结果”。

### 必做工作

- 每次审核冻结 decision_id、eligible plan IDs、snapshot/input/prompt/model 版本及 response deadline。新旧响应不能串用，输入变化不得复用旧审核结果。
- 每个 eligible plan 恰好一个结果，`llm_veto` 必须是严格 JSON 布尔，不能 `bool("false")`、`bool(0)` 或把缺字段默认通过。
- 缺少对象、重复 ID、未知 ID、错误输入身份、超时、schema 非法、非有限数字/越权字段按已定义严格策略阻断本次入场审核，并产生稳定错误码。若选择局部阻断，必须逐条有充分身份与覆盖证明；默认不能把未覆盖项放行。
- 模型价格、数量、新标的、动作建议不得改变正式计划或风控。真实下单功能始终禁用。
- 需要否决理由时，reason_code 和 evidence_refs 必须能对应输入证据。不存在的引用不能被当作真实风险事实，应标记审核失败，不用它训练“正确否决”标签。
- 模型拒绝、不确定、超时是不同观测结果，不能统计成同一种成功否决。
- 网络失败和超时总预算包括连接、重试、流式读取与解析，迟到输出不得授权已过期订单。维持持仓退出独立。
- 保存允许的结构化结果、理由码、引用、实际 latency、尝试次数、输入输出 token、可计算的成本及模型返回标识；无价格表时成本为未知，不编造。
- 对外部文章、HTML、资料中的提示词注入做不可信文本隔离，模型不能触发 arbitrary tool/network actions 或修改权限。
- 修复当前 callback 到事件账本的理由/引用丢失路径。底层 API 与实际 workflow 回调两层都写集成测试。

### Flash 对照实验

建立隔离实验配置：同一个确定性信号流，分别“无模型否决”和“有模型否决”。前者只用于独立影子账本，不是正式故障自动放行模式。

固定行情、成交模型、费用、资金、风险预算，分别统计：避免亏损、错失盈利、模型失败漏做、延迟成本、调用成本以及账户机会替代效应。只有扣除全部代价仍有稳健改善，才提出调整正式模型使用方式。

### 必测

- `LLM-01` 合法 pass/veto 正确，未知 ID、漏项、重复 ID、字符串 false、null、额外权限字段均按严格规则处理。
- `LLM-02` 模型生成新标的、买价、数量不能进入订单。
- `LLM-03` 迟到/旧快照响应、异常流式返回、连接无响应不绕过总 deadline。
- `LLM-04` 关键数据不足不借模型补全；模型超时不影响确定性保护性退出。
- `LLM-05` 注入恶意文章不能改权限或来源身份；虚构 evidence_ref 不被记录成有效否决证据。
- `LLM-06` 影子无模型实验与正式通道物理账本/输出路径隔离，不共享资金或预占。
- `LLM-07` 模型输出 schema 合格也必须验证引用与候选集合；解析成功不能等同审核有效。


## S08. 前后端展示与研究/交易语义一致

### 目标

修复“CORE 看起来等于可以买”“所有股票显示同一主题分数”“任务成功掩盖数据降级”等误导，不改变策略门槛。

8. 页面刷新只读已发布快照与任务状态，不能每刷新一次就触发全市场采集。手动刷新也遵守 Provider 闸门。
9. API 字段变化添加契约测试与迁移兼容；CSV/Markdown/前端/通知使用同一投影。真实通知仍在测试中禁用。
10. 数据源健康页按能力列出最近成功、数据年龄、有效覆盖、最近失败原因、下次尝试、影响路径；避免一个“源正常”的灯覆盖不同能力的故障。

### 必测

- `UI-01` A3 条件计划带盈亏比不足时，显示待确认，不显示可立即买入，也不错误说确定性风控被绕过。
- `UI-02` 同主题多股主题分相同，但个股角色/相对强度各自正确。
- `UI-03` 必需数据缺失与非关键降级总状态正确，缺值不显示为 0%。
- `UI-04` API、前端、Markdown、通知投影的数量、状态、源身份一致。
- `UI-05` 轮询 100 次不会触发 100 次远程抓取；旧快照有清晰年龄与用途限制。
- `UI-06` 类型检查、现有前端测试与 build 通过，无敏感凭证下发。

## S09. 补充源旁路验证与 easy-stock 思路的独立实现

### 目标与边界

只补确有缺口的能力。先旁路采集、归一化、对账、评估，再决定是否提出正式源变更；新增源默认 `enabled=false / shadow_only=true / execution_authority=false`。

本阶段完成标准分两层：适配器代码和离线契约测试；真实网络、授权、时效与覆盖的独立验收。代码能处理 fixture 不等于真实源已可用。

### 候选能力及限制

**A2 题材/梯队补充。** 可研究短线侠承载的开盘啦相关数据，但必须如实记录实际提供方与上游链。题材、连板角色、首封时间等先作为旁路证据。不能默认官方直连，不能自动继承 easy-stock 的主源优先级、融合权重或排名常量。

**A1 业务与财务摘要。** 独立适配授权可用的公司资料和 F10 摘要接口。分开存原文、提取摘要、行业回退标签。只有最新一期、没有公告时间时，明确标记不是多期三表和严格 PIT 数据；不能用行业名称冒充主营收入。

**报价备用。** 选择合法可用且字段契约可核实的报价能力，优先减少当前报价单点。先做同交易日、时间戳、股票代码、单位、价格边界、停牌等对照；相同上游不算两源验证。

**观点资料。** 放到 A1/A2 研究线索或 A5，不进入 A4 每分钟关键依赖。保存作者、原文、时间、来源链、转载/重复组、提出的可检验条件和观点失效期。缺作者授权/浏览器登录环境时提供合法导入接口，不能绕过访问限制。

### 集成要求

- 接入 S02 的能力注册和限流，接入 S04 的覆盖账本与 S01 的来源契约；不另建一套无法追溯的缓存。
- 原始事实、派生特征、作者观点、模型解释分别存；事实变化不会直接把模型结论变成策略规则。
- 使用同一时间和相同对象范围做对照，报告真正新增的有效字段/对象数、冲突率、延迟、旧数据比例、数据年龄和任务资源开销。
- 有主源缺口且备用合格，可以在明确审批后的来源配置版本中切换；影子阶段不影响 ACTIVE/FOCUS/CORE、A4 或收益。
- 文档写明第三方许可与上游条款核查结果；无法授权者保留禁用，不提交来源受限代码、密钥或绕过机制。
- 不能以假返回值或仅创建空类宣称适配完成。真实能力不可用时标记 `ADAPTER_OFFLINE_TESTED / LIVE_UNVERIFIED` 或 `UNSUPPORTED`。

### 必测

- `SRC-09` 新源启停对正式候选/订单结果无影响，旁路投影可见。
- `SRC-10` KPL 标签、目录概念、主营资料三类身份不互换。
- `SRC-11` 只有 HTTP 文件时间、无可靠交易日时不能标为当前可交易快照。
- `SRC-12` 观点转载十次只算一条来源链，不形成十票共识；过期观点不能授权交易。
- `SRC-13` 业务原文提取失败时，行业回退显示为分类，不伪造业务占比。
- `SRC-14` 源未经授权、网络不可用或口径未验收时，不开启正式 fallback。

## S10. 分层增益、反事实、回放与策略改动治理

### 目标

复用 `evaluation/outcome_labels.py`、`a4_replay.py`、`replay_window.py` 和 A5 等已有能力，建立可信对照，不重新搭平行回测引擎。

### 两类数据集，不能混用

1. **忠实回放 AS_OBSERVED**：使用当时可用的行情、财务/公告版本、主题成员、计划、LLM 结果、接收时刻、配置和费用/成交模型。
2. **修复回放 REPAIRED_DATA**：使用补齐/更正数据，明确修复内容、实际补数时间和不能声称当时可交易的限制。

二者隔离 run_id、报告与成绩单。不能用今天模型重新推理的历史输出替代当时模型审核；重新推理实验另标 `RETROSPECTIVE_MODEL_RESEARCH`，说明模型内部未来知识风险。

### 研究与账户成绩单

- 研究层：候选覆盖、未来 1/3/5/10 日与适用更长窗口的收益、同类条件基准超额、最大有利/不利波动、各准入路径与数据等级的结果。窗口按策略持有契约配置，不能所有路径只看次日。
- 账户层：真实模拟成交后的费用/滑点净收益、回撤、资金利用、换手、成交率、持有期、未成交、退出受阻、集中暴露。没有足够样本，不输出确定盈利结论或伪精确胜率。
- 分开记录“选后上涨”和“系统实际可成交盈利”。收盘后选出的股票不能拿当日收盘成交收益充当可实现收益。
- 收益基准的价格复权、公司行动、交易日与可交易范围和策略保持可比，不默默丢掉退市、停牌或无收益标签的样本。

### 分层对照

预定义实验：基础技术基线、加入 A1 筛选、加入 A2 筛选、完整 A3/A4、再加入模型否决。

- 去掉一层筛选不代表删掉所有客观风控；固定同样的数据可用时点、基本交易资格、成交模型、费用和资金约束。
- 每个阶段是否使用模型、服务端规则如何覆盖输出，要从当前实际调用路径记录，不能按 Agent 名字假设模型贡献。
- 固定配置、随机种子和日期划分，保存所有实验版本，禁止只报告最好的组合。
- 三条策略分别按市场环境、入场模式、目标来源、持仓周期评估，再汇总组合；不把不同风险路径混成单一胜率。
- A1 按准入来源分组；A2 按主题与市场角色分组；A4 按确认条件做消融；Flash 单独衡量延迟与错失机会。
- 券商金股若参与准入，不再将同一数据的高覆盖率当成独立盲测收益基准。分离“覆盖检查”和“未参与选择的留出对照”。
- 同日同题材股票存在相关性；统计区间考虑交易日/主题聚类。采用时间顺序 walk-forward，按持有标签重叠情况做 purge/embargo，不能随机拆行制造独立样本。
- 门槛和统计方法须在看结果之前登记。样本不足显示 `INSUFFICIENT_EVIDENCE`，不把少量有效单放大成年化结论。

### 规则变更流程

每项策略门槛调整形成独立 `CONFIG_CHANGE_PROPOSAL`：假设、影响范围、冻结版本、训练/验证窗口、全部试验列表、对照、成本/风险、验收门槛和回滚。A5 和模型只能提出建议，不能直接修改生产配置。当前迭代默认实现评价能力，不替用户自动选择“最赚钱参数”。

### 必测

- `EVAL-01` 修改未来行情/财务修订，不改变历史决定；标签可以在到期后追加但不改决定身份。
- `EVAL-02` 忠实回放与修复回放明确隔离，证据缺失不自动补成完整忠实回放。
- `EVAL-03` 同决策/订单/成交链重复回放结果一致；跳过/受阻/未成交不算盈利交易。
- `EVAL-04` 不同费用/撮合/策略版本分开出报告，旧结果不覆盖。
- `EVAL-05` 固定实验切分，检测标签窗口重叠与未来成员/复权/公告污染。
- `EVAL-06` 模型否决实验信号级与账户级分别计算，不能简单相加忽略资金机会替代。
- `EVAL-07` 人为放入未来公告、错日期主题、未知复权、成本遗漏等反例，验证器必须报错，不能硬编码“符合策略文档=True”。
- `EVAL-08` 空样本/极少交易输出不足证据；条件基准与被测样本不相互污染。
- `EVAL-09` A1/A2 各去向集合能对账，保留未入围样本用于研究，不用最终成功股票倒推筛选质量。

## S11. 集成验收、迁移演练、影子运行与回滚

### 验收等级

最终分别给出：

- `CODE_ACCEPTED`：代码、确定性测试、类型检查、构建、负例和契约通过。
- `REPLAY_ACCEPTED`：在明确列出的历史数据与时间资格下完成隔离回放，修复差异有解释。
- `OPERATIONS_ACCEPTED`：在目标运行环境完成持续影子稳定性与故障恢复验证。
- `STRATEGY_EVIDENCE_SUFFICIENT / INSUFFICIENT_EVIDENCE`：策略统计证据是否足以支持后续参数变更。
- `DEPLOYMENT_APPROVAL_REQUIRED`：即使上述通过，切换生产主通道仍需单独授权。

不存在一个能用“代码测试 PASS”代替所有等级的总 PASS。

### 总验收入口

最终实现跨平台 Python 入口，优先复用现有测试系统：

```text
python scripts/run_iteration_acceptance.py --profile offline --output-dir artifacts/iteration/<run_id>
python scripts/run_iteration_acceptance.py --profile replay --manifest <readonly_manifest> --output-dir <isolated_output>
python scripts/run_iteration_acceptance.py --profile stress --scenario <scenario_name> --output-dir <isolated_output>
python scripts/run_iteration_acceptance.py --profile shadow-report --manifest <observed_manifest> --output-dir <isolated_output>
```

这些是目标命令。若合并至现有 CLI，必须在 RUNBOOK 中提供真实等价命令，`--help` 与集成测试证明可用，不能只留下伪代码。

`offline` 默认禁止公网/模型/通知/生产写入；依赖安装是单独准备阶段，不在离线测试内部静默联网。跨平台不要依赖 Bash 专有语法或 Windows 特定计划任务。

返回码要求：0=该 profile 的必需验收全部通过；1=实际失败；2=参数/配置错误；3=缺必需环境或证据导致未完成；4=保护策略阻止危险运行。缺少数据不能返回 0 并声称全项目通过。可选用例跳过必须记录，不影响必需验收未完成的真实状态。

结果 summary 至少含 profile、状态、基线/测试提交、环境、输入哈希、执行命令与退出码、测试计数、要求到测试的映射、失败/缺证据项、开始结束时间和产物目录。

### CI 与依赖

- 跑当前仓库原有 Python 测试、覆盖报告、前端类型检查/测试/build。参考基线 CI 的覆盖门槛为 65%，不得降低；记录当前实际基线总覆盖并解释变化。
- 新增核心纯逻辑模块的分支覆盖建议至少 90%，资金/时序/权限的列举负例必须全部覆盖。旧超大文件不以行覆盖百分比代替业务性质验证。
- 不通过删除失败测试、改期望为错误行为、使用 skip/xfailed 掩盖缺陷。已有设计变化的测试需说明旧新契约和影响。
- 外网契约与模型能力探测独立、显式 opt-in，不让普通 CI 依赖不稳定公网接口；真实失败影响源验收，不直接伪装成策略回归。
- 依赖锁定或至少保存可复建版本清单，遵循已有工具。安全扫描需要网络时说明；不盲目执行强制升级或引入未经审查大依赖。

### 数据库迁移

- 使用版本化、幂等、增量迁移；尽量添加表/字段/索引，不删除历史账本。
- 在生产一致性副本上迁移演练，比较迁移前后记录数、资金/持仓/成交校验、关键索引和完整性。
- 明确旧代码能否读取新 schema，不能假定关闭 feature flag 就能回滚数据库。
- 在线新成交后不得通过恢复旧备份丢弃已经发生的事件。回滚优先撤功能与前滚修复，或使用经验证兼容适配；确需快照恢复，必须有停写窗口和快照后事件补放方案。
- 用回滚演练确认未成交单/退出意图、预占和持仓均保留，不双写不双发。

### 影子运行

先执行离线与回放，再由用户授权在虚拟机独立命名空间运行影子版本。默认不开真实通知、不共享订单/资金/写目录，不影响正式调度。

建议至少观察连续 5 个完整实际交易日，包括开盘、午休、收盘边界；这是操作稳定性建议窗口，不是策略盈利证明，也不能等待未来数据阻止当前代码交付。若未完成则记录 `PENDING_PRODUCTION_EVIDENCE`。

预先冻结操作验收目标：

- 无重复成交、无负现金/非法卖出、无使用未来数据授权、无漏记的关键调度时点、无资金预占泄漏。
- 非关键源故障不阻断可信数据支持的持仓保护，注入全局完整性故障时按设计安全阻断。
- 按时终态率建议≥99.5%，同时报告数据可评估率、报价覆盖率、模型成功率和真实无机会率；不得靠全部 BLOCK 达到指标。
- 阶段耗时、p95/p99、积压、任务线程/进程数和数据库等待无持续恶化。
- A1 所有应覆盖对象有明确去向；有限模拟故障恢复后积压按预算减少。外部源不支持的字段允许存在，但须列明并禁止被错误声明“已补齐”。

上述操作目标是建议的验收配置，应在运行前固定，不得看结果后降低。真实外部数据覆盖的目标由 S00 测得基线和必需字段契约确定，不承诺任意免费源达到 100%。

### 必测与交付

- `OPS-01` 一键入口在干净隔离环境可执行，能检测失败与缺环境，不硬编码 PASS。
- `OPS-02` 迁移重复执行、迁移中断、回滚/前滚演练不丢账本。
- `OPS-03` kill/restart、网络中断、慢源、LLM 超时、磁盘满、数据库锁及损坏输入均有实际测试证据。
- `OPS-04` 影子目录/通知/账户和正式路径隔离，path guard 覆盖符号链接与误配置。
- `OPS-05` 前述所有必需测试 ID 绑定真实测试函数与真实执行结果；无证据项自动显示未完成。
- `OPS-06` 每个建议新增命令都能执行，所有配置有 schema 校验，不存在无调用方的“完成模块”。
- `OPS-07` 从下述生产证据包能够自动生成稳定性与覆盖报告，不依赖人工编造摘要。

最终交付 `IMPLEMENTATION_REPORT.md`、`FINAL_ACCEPTANCE.md`、可执行测试入口、迁移脚本/演练、真实测试报告、待证据清单、配置差异、部署/回滚手册。不部署生产；不得以“代码写好了”代替运行验证。

## B. 生产证据包：不需要开放数据库外网

实现或复用安全导出工具。仅在已有授权的本机路径中操作，不自行寻找 SSH 密钥或把资料传给第三方。

包中至少包含：

## C. 防止“假完成”的最终自检

结束前逐项回答，并给证据路径：

1. 是否有真实代码修改，而不只是本文的另一个版本？新增模块是否由现有运行入口调用？
2. 原有 baseline 是否实际执行？没有执行的原因是什么？
3. 缺口和保护性故障测试是否真的触发了失败分支？
4. 是否保护旧规则、历史数据和生产配置，没有通过放宽规则让测试变绿？
5. A4 已就绪股票是否仍等待无关归档/辅助任务？持仓风险是否仍等待全市场取数或 LLM？
6. A1 统计是否保持同分母、同范围、同截止时间，是否逐层列出消失对象？
7. 所有影响历史决定的时间字段是否真实，是否存在未来 close/修订/审核完成前撮合？
8. 最低佣金、部分成交、T+1、资金预占、重启恢复是否可核对？
9. 模型错误/缺项/过期响应是否能错误放行？退出意图是否被过粗去重键吞掉？
10. easy-stock 参考是否限于授权允许范围，新增数据源是否默认旁路？
11. 新旧版本回放差异是否逐对象解释，是否区分忠实回放和补数回放？
12. CODE / REPLAY / OPERATIONS / STRATEGY 四类验收是否分别真实表达？

绝不输出“全部完成”而在正文藏着未跑的关键测试。最终可以是“代码阶段通过、生产证据待补”；这是合格的诚实交付，但不是上线许可。
