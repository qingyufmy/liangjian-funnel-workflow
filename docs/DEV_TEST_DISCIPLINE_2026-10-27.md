## 一、问题不是偶发，是同一个模式

近 3 天出的问题，几乎都是"改了上游，没改下游"或"新的上了，旧的没下"：

|---|---|---|---|

| 10 | 13:21 候选 3、cap 2，一只静默丢弃 | 加了单节拍上限 | 没有截断记录/排队/告警 |

**根因（5 条）**
1. **没有下游清单**：改一个生产者时，不知道谁在消费它（A5、推送、UI、看门狗、通知、文档）。
2. **测试只测改动的那一块**：没有"用最近一个真实交易日，从盘前跑到复盘、看所有对外输出"的整体验收。
3. **迁移不收尾**：新组件上线后，旧组件既不删除也不降为影子，形成双裁决、双口径。
4. **静默降级被允许**：catch 吞异常、未知 code 显示"未识别"、超上限直接丢——问题被藏起来，到盘中才暴露。
5. **验收看"流程跑通"，不看"输出对不对、读不读得懂"**。我的 FINAL ACCEPT 也犯了这条：只核目标缺陷的门，没核下游和对外输出。

## 二、十条纪律

### D1 改动必带"下游清单"
- 仓库维护 `docs/CONSUMER_MAP.yaml`：每个生产物（表、文件、事件、code 枚举、推送类型、配置路径）→ 全部消费者。
- 每个改动的交付件必须列出受影响消费者，逐个给出"已改 + 测试名"或"无影响 + 理由"。缺一项不得提审。

### D2 契约单一来源 + 版本
- reason/condition code、动作枚举、中文标签、时区、生产路径、阈值：只在一处定义，其他地方引用。
- 每个消费者声明它消费的契约版本；部署时检查：消费者落后于生产者主版本 → FAIL（专治"A5 还是很早的版本"）。
- CI 枚举门：生产代码能产出的每个 code，都必须在标签字典里有中文，缺一个 FAIL。

### D3 迁移必须收尾
- 新组件替代旧组件时，同一份任务书写明：唯一裁决者是谁；旧组件"删除"还是"影子运行到某日"。
- 不允许两个组件同时对同一决策有效（今天 legacy + Team 就是反例）。

### D4 禁止静默降级
- 禁止 catch 后不记原因；未知 code 显示原始 code + 计数告警；超上限必须记 TRUNCATED 并推送；任何兜底都有独立状态名（如 JUDGE_TIMEOUT，不得混叫"数据阻断"）。

### D5 真实交易日整日回放门（发布必过）
- 用最近一个真实交易日的原件，跑完整链：盘前 → 晨会/CAS → 激活 → 盘中 A4 → 收盘链 → A5 复盘 → 全部推送。
- 对比项：所有计数与生产账本逐项相等；所有对外文本（飞书卡片、A5 报告、UI）生成快照，人工抽检 + 自动规则（见 D8）。

### D6 真实路径性能
- 性能门必须包含真实模型延迟（用当日录得的 p95 注入）和真实网络重试路径；线上必须有分段计时（取数/packet/技术/模型/写账）。没有分段计时 = 性能门不成立。

### D7 提示词与校验器联测
- 改提示词或校验器，任一方都要用最近真实模型回复集合回放另一方，拒绝率与改前对比；附负例。
- 每次模型请求的渲染全文、原始回复落盘并哈希绑定，否则无法复盘（今天 10:31 就无法完整还原）。

### D8 对外输出门
- 每种推送/卡片/A5 报告都有快照测试。出现以下任一即 FAIL：未识别/未知/None/null 字样、非北京时间、字段截断无提示、价格区间与当前绑定口径不一致、计数与账本不符。

### D9 完成的定义包含下游
- 一个改动"完成" = 生产者 + 全部消费者 + 运维脚本（看门狗、定时任务、通知）+ 文档都更新并通过 D5/D8。只改生产者的交付视为未完成。

### D10 审批纪律（Claude 自身）
- FINAL ACCEPT 前必须看到：D1 清单、D5 整日回放结果、D8 对外输出快照。三者缺一，不批。
- 每次发布后第一个交易日，按清单逐个消费者核一遍，不只核这次修的那个点。
